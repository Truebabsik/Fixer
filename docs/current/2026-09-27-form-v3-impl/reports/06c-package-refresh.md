## 2. Как устроено решение

**Почему комплект вырос с шести модулей до двенадцати.** Правка **M6** (ревью 01–04) убрала у формы
свой список видов эффектов: `const EFFECT_TYPES := Sim.EFFECT_TYPES`, где `Sim` — `preload("res://sim/sim.gd")`.
`preload` разрешается на разборе, поэтому копия валидатора без ядра не компилируется вовсе. Ядро
`sim.gd` само подтягивает `agent`, `radio`, `scales`, `response`, `understanding`, `window`. Полное
замыкание от `content/validator.gd` + `content/loader.gd` — **12 файлов**; других динамических загрузок
(`load(`, `ResourceLoader`) в замыкании нет (проверено поиском), то есть список полон.

**Почему в шести из них правлены комментарии.** Боевые модули уезжают наружу **копиями**, и правило
пакета (`kit/verifier/selfcheck.gd`, правило `dnn`) запрещает в них наши внутренние номера решений и
пути к нашим документам. Шесть модулей замыкания этим правилам не удовлетворяют — на них 33
срабатывания (§3.3). Штатное место правки — `game/**` (так задача 06а и поступила с `validator.gd` и
`problems.gd`, убрав оттуда `D48`): но `game/**` мне запрещён, поэтому правка сделана **в копиях**:
удалены/переписаны только фрагменты **комментариев** и один служебный `note`. Построчная сверка
(§3.3) подтверждает: **ни одна строка кода не изменена** — все 33 различия лежат в строках, которые
начинаются с `##` (в образце — один `note`, который ядро не читает).

**Что это значит для получателя.** Валидатор, коды, загрузчик и `mission/plan/response` — побайтовые
копии (§3.2). Ядро отличается от нашего **только прозой комментариев**; поведение то же, и это
доказано прогонами: исправленные правила на комплекте краснеют ровно там, где краснеют у нас (§3.5–3.6).

## 5. Решения вопреки брифу

1. **Комплект — двенадцать модулей, а не шесть.** Бриф называет шесть; после правки M6 копия
   валидатора без ядра не компилируется (§3.1). Без добавления шести файлов не выполняется ни один
   обязательный прогон: `verify.gd` не запускается вовсе. Альтернативы (оставить прежний валидатор
   или подсунуть копии урезанное ядро) означали бы либо не отдать получателю исправленную форму, либо
   отдать выдуманный модуль вместо нашего.
2. **В шести копиях ядра правлены комментарии** (33 замены). Это отступление от «копия = боевой файл»,
   и оно названо в `kit/verifier/README.md`. Причина: боевые модули содержат наши внутренние номера и
   пути (§3.3), то есть **копии в их нынешнем виде нарушают правило пакета** — то же, что задача 06а
   нашла и починила у `validator.gd`/`problems.gd`, только теперь в ядре. Штатное место правки —
   `game/**`; моя область её не включала (§6.1).
3. **Образец переложен из канонического контента, и в нём убран один токен `(D48)`.** Бриф называет
   только шесть модулей, но без перекладки образца обязательный прогон «валидатор на образце: 0
   проблем» невозможен (прежний образец даёт три диагноза, §3.4), а без удаления токена `selfcheck`
   краснеет на своей же копии. То́кен стоит в служебном `note`, ядро его не читает, поведение образца
   не меняется.
4. **Правлены не только «документы формы» (`01-format.md`), но и `00-task.md`, `02-level.md`,
   `07-self-check.md`, `08-report.md`, README пакета и README комплекта.** Бриф говорит «если в тексте
   есть расхождение с кодом — правишь текст пакета»: те же два правила были изложены неверно ещё в
   четырёх документах и в README комплекта, и оставить их значило бы отгрузить получателю два
   взаимно противоречащих описания одной формы.
5. **Гейт (`preflight`/`run.gd`/`run_red.gd`) снят сверх брифа** — чтобы постоянные ворота
   репозитория (в том числе `test_package_purity.gd` на **этот** пакет) были проверены на финальном
   состоянии, а не на слове.
