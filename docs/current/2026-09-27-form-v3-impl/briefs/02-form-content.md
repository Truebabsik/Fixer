# Бриф: форма, валидатор и канонический контент под v3

Ты — исполнитель. Читай **сначала** `docs/agents/constraints.md` (общие правила, гейт, грабли среды) и
`docs/current/2026-09-27-form-v3-impl/plan.md` §«Контракт» — имена, формы и правила зафиксированы там,
переименовывать их нельзя. Коммит не делать. Субагентов не вызывать.

## Где это в проекте

Форма контента живёт в `game/content/validator.gd` (+ `problems.gd` — коды диагнозов), канонический
артефакт — `game/content/mission-01.json` и `texts.ru.json`, постоянный кейс на нём —
`game/tests/cases/test_mission01_delivery.gd`. Решения, которые ты реализуешь, — **D45–D48, D50, D52**
в `docs/desions.md` (прочитай: там сказано, почему так и что остаётся заделом).

**Зачем.** Приёмка внешней поставки нашла прогоном то, что форма обязана была сказать статически:
окно на сенсоре, куда не заходит ни один патруль (не срабатывает никогда); окно `node_entered` на
**входном** помещении (группа там стартует — события входа нет); разведку-«призрак», дословно равную
реальному патрулю; норматив «окон за прохождение», который нечем измерить, потому что маршрутов уровня
нет в данных; раздел `access_points`, который ядро не исполняет вовсе.

## Что сделать

1. **Три диагноза «окно невозможно»** (D46): (а) `guard_in_sensor`, чей сенсор не посещает **ни один**
   патруль; (б) `node_entered` на узле с тегом `entry`; (в) якорь любого окна недостижим от входов по
   рёбрам. Каждому правилу — **свой код**, докажи каждое пробой.
2. **Раздел `routes`** (D47): обязательный; ровно один маршрут на каждый узел с тегом `entry`;
   `entry`/`exit` — узлы с тегом `entry`; `route[0]` = `entry`, `route[-1]` = `exit`; цель лежит на
   маршруте; каждая пара соседей соединена ребром. Каждое из этих правил — свой диагноз.
3. **Призрак обязан расходиться** (D48): для каждого пункта разведки вида `patrol` маршрут **и** период
   отличаются от реального патруля с тем же `id`.
4. **Убрать `access_points` из формы** (D52): раздел больше не принимается (неизвестный корневой ключ —
   существующий диагноз), действия у терминала выражаются вариантами окон.
5. **Тег `shielded`** и **эффекты** `money`/`trace`/`mark` — признать допустимыми (D49/D50); эффекты
   исполняет ядро (делает другая задача — тебе важно, что форма их **принимает** и валидирует типы).
6. **Привести канонический контент к новой форме** — так, чтобы дерево осталось **зелёным**:
   дописать три нормативных маршрута (`routes`) для текущей топологии; перенести действия терминалов в
   окна (или снять их, обосновав); поставить тег `shielded` подвальным помещениям по смыслу уровня;
   починить те окна, которые покраснеют от новых диагнозов (**данными**, а не ослаблением правила —
   если правило кажется неверным, это стоп и вопрос ведущему). Тексты новых вариантов — в
   `texts.ru.json` по ключам. Числа в `test_mission01_delivery.gd` (28/35/11/203/18 и т. п.) —
   **факт артефакта**: поправь их вместе с контентом и скажи в отчёте, какие стали.

## Доказательство

Мутационные пробы (копии в `%TEMP%`, ломаем **данные**), по одной на каждый новый диагноз — минимум:

| Проба | Что сломать в копии данных | Что обязано покраснеть |
|---|---|---|
| M1 | убрать ребро так, чтобы в зону сенсора окна не заходил патруль | диагноз «сенсор без патруля» с путём окна |
| M2 | перенести якорь окна на входное помещение | диагноз «окно на входе» |
| M3 | сделать якорь окна отрезанным от входов | диагноз «недостижимый якорь» |
| M4 | убрать один маршрут из `routes` | диагноз «не ровно один маршрут на вход» |
| M5 | разорвать маршрут (пара соседей без ребра) | диагноз «маршрут не по рёбрам» |
| M6 | сделать разведку равной реальному патрулю | диагноз «призрак равен реальности» |

Плюс: канонический контент проходит валидатор с **0 проблем** и миссия собирается; гейт
(`preflight` → `run.gd` → `run_red.gd`) — коды 0. Пробы, покрасневшие не тем диагнозом, — не пробы.
