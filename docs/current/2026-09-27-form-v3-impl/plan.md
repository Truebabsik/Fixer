# Задача: реализация формы и ядра под v3 (2026-09-27)

## Откуда задача

Фаза требований закрыта: `docs/current/2026-09-27-form-v3-requirements/` (решения **D45–D54**).
Приёмка v2 дала вердикт «принять с замечаниями, перенос отложен» — потому что корень найденного
в **нашей форме**, а не в поставке (`docs/current/2026-09-27-mission-01-v2-accept/summary.md`).

Здесь — **реализация**: код, форма, валидатор, инструмент, контент, документы. Решения не
пересматриваются; если реализация вскроет, что решение невыполнимо, — стоп и возврат к владельцу,
а не тихая подмена.

## Контракт (пинning: имена и формы зафиксированы здесь, чтобы исполнители не разошлись)

| Что | Точная форма |
|---|---|
| Тег экранированного помещения | `shielded` в `nodes[].tags` |
| Эффект-счётчик | `{"type": "money", "value": <int>}` и `{"type": "trace", "value": <int>}` |
| Эффект-метка | `{"type": "mark", "id": "<строка>"}` |
| Поля результата прогона | `money: int`, `trace: int`, `marks: Array[String]` — **отсортирован по алфавиту** (детерминизм отпечатка) |
| Раздел маршрутов | `routes: [ { "id": str, "entry": node, "exit": node, "route": [node, …] } ]` — **ровно один на каждый узел с тегом `entry`** |
| Правило актёров | сцена про человека/ситуацию в помещении — `node_entered`; `guard_in_sensor` — только про охрану |
| «Понимание» | спрашивается **минимум по живым своим** (самое слабое звено исполняет): `complexity > understanding` ⇒ буквальное исполнение с надбавкой |
| Терминалы | действия у терминала — варианты окон; раздел `access_points` из формы **удаляется** |

Надбавка за буквальность — числа в `docs/spr/mercs.md` §1 (дописать и обосновать, если их там нет).

Заодно канонический контент становится **эталоном новой формы** — из него собирается пример для пакета.

## Приёмка задачи

1. Решения D45–D54 реализованы; каждое изменение доказано мутационной пробой с именованным ассертом.
2. Гейт: `preflight` → `run.gd` → `run_red.gd` — коды 0, `failed: 0`; новые инструменты разбираются
   `preflight`.
3. Канонический контент валидируется новым валидатором с **0 проблем** и играется: инструмент приёмки
   на нём даёт вердикт по критериям, норматив считается по объявленным маршрутам.
4. Документы не расходятся с кодом: `design.md`, `architecture.md` §2.2/§5, `spr/mercs.md` §1.
5. Пакет v3 собран, самодостаточен (проверка чистоты), образец проходит **наш** валидатор и **наш**
   инструмент, и в пакете стоит обязательный пункт приёмки с этими прогонами.

## Вне задачи

- Баланс (порог тревоги, цена контакта, выезд против отхода) — после того, как форма и маршруты сядут.
- Презентация (П2) — после баланса.
- Приёмка будущей поставки v3 — отдельной задачей, когда она придёт.
