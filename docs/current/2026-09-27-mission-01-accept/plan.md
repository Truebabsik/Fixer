# Задача: принять поставку миссии 01 (2026-09-27)

## Откуда задача

Внешняя сессия сдала контент миссии 01 по пакету `docs/handoff/2026-09-26-mission-content/`.
Поставка лежит в `levels/mission-01-content/` (вне git на момент старта): `mission-01.json`,
`texts.ru.json`, `report.md`.

**Замер приёмки (ведущий, до задачи).** Поставка **не проходит наш конвейер**: `Validator.validate`
даёт **49 проблем**, `Loader` миссию не собирает. Разбор по корням:

| Корень | Проблем | Наш контракт |
|---|---|---|
| `silence` = `{text_key, by, effect}` вместо четырёх исходов | `MISSING_SILENCE` ×11 + `UNKNOWN_KEY` ×22 | `02-format.md` §4.5: четыре исхода массивами; поля `by` нет |
| эффект `reroute` (5 мест) | `BAD_VALUE` ×3 + `UNKNOWN_KEY` ×9 | `02-format.md` §4.4: снят намеренно, поиска пути в ядре нет |
| `trace_key` в `access_points` | `UNKNOWN_KEY` ×3 | поля нет ни в валидаторе, ни в §6 |
| `w_stuck_lift`: `locked_edge` на **открытом** ребре | `WINDOW_ON_OPEN_EDGE` ×1 | `_check_silence`: окно у двери требует `locked: true` |

**Контрольный замер.** Нормализация копии строго по контракту (шаблон §4.5; `reroute` → рецепт §4.4
«`delay` + `engine_proposal` с `fallback`»; `trace_key` убран) дала **4 проблемы**: 3 `DANGLING_TEXT`
(ровно `ap.*.trace`) и 1 `WINDOW_ON_OPEN_EDGE`. То есть 45 из 49 — механическая порча формы.

**Почему не поймали раньше.** В `07-report.md` нашего пакета есть строки приёмки «четыре исхода»,
«в `silence` нет `by`», «в эффектах нет `reroute`» — в отчёте генератора эти три строки **отсутствуют**,
а «11/11 молчаний» проверено их собственным `validate_mission.py`, кодировавшим их же схему.
Наш валидатор на поставке не прогонялся ни разу.

## Решения владельца (2026-09-27, обсуждение архитектуры)

1. **`reroute`: сначала дизайн плана Б, потом форма.** Контракт `reroute` сейчас **не расширяем**.
2. **План Б (перенос группы) — отдельной задачей после первых замеров.** Сейчас данные идут
   рецептом §4.4: `delay` + `engine_proposal` с `fallback` на тот же `delay`. Обход как поворот
   группы **не работает** — он стоит времени и ждёт движка.
3. **`w_stuck_lift`:** контракт расширяем («ребро запираемо» = заперто **или** блокируется тревогой),
   и ядро снимает блокировку при выходе из окна.
4. **`trace_key` принимаем в схему** как известное необязательное поле; `ap.*.trace` перестаёт быть висячим.

Причина отсрочки п. 1–2 записана в `ledger.md`: поиск пути не нужен (эффект несёт готовый `node`),
но маршрут сегодня — один общий список на группу из плана (`sim.gd:100`), а переносить придётся
каждого своего по его позиции; у ядра нет ни «плана Б», ни правила возврата на исходный маршрут.
