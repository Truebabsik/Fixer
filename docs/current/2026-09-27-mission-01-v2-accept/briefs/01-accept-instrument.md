# Бриф: приёмочный инструмент для поставки уровня

Ты — исполнитель. Читай **сначала** `docs/agents/constraints.md` — там общие правила, команды и грабли

## Где это в проекте

Пришла внешняя поставка уровня: `docs/handoff/2026-09-27-mission-01-delivery/` — новая топология
миссии 01 (28 помещений, 35 рёбер, 16 окон). Форму она уже проходит (наш валидатор: 0 проблем),
**смысл не проверен**: берётся ли цель прогоном от каждого входа, срабатывают ли окна на реальных
маршрутах, доходит ли группа до выхода, достижим ли провал. Инструмента для этого в репозитории нет:
`game/tests/measure_mission01.gd` и `game/tests/cases/test_mission01_delivery.gd` привязаны к
топологии v1 (id помещений, рёбра, рукописные маршруты).

Процедура и критерии утверждены: `docs/current/2026-09-27-mission-01-v2-accept/design.md` §2–3 —
читай до начала работы, коды критериев оттуда.

## Что сделать

1. **`game/tests/accept_delivery.gd`** — инструмент (extends SceneTree), запуск:
   `--headless --path game --script res://tests/accept_delivery.gd -- <путь mission.json> <путь texts.json>`.
   Стадии, по порядку (падение стадии 1–2 прекращает прогон — дальше судить нечего):
   1. **форма**: боевые `content/validator.gd` + `content/loader.gd`; проблемы дословно
      (`[КОД] путь — сообщение`), затем строка `СОБРАНО:` (помещения/рёбра/патрули/сенсоры/окна/
      разведка/точки доступа);
   2. **геометрия**: `pos` у каждого помещения (обе оси целые), помещения одного этажа не наезжают
      (коробка 3×3, шаг сетки 4 ⇒ расстояние Чебышёва ≥ 4), `name_key` у помещений, `floors` и
      `facility_key` имеют тексты;
   3. **связность**: входы — узлы с тегом `entry` (объяви критерий `ENTRIES_DECLARED`: их не меньше
      трёх); цель достижима от каждого входа; от цели к выходу ≥ 2 путей, и существует путь, не
      использующий рёбра видов, перекрываемых тревогой (список видов — **из ядра**,
      `sim/response.gd:BLOCKED_KINDS`, не своим списком);
   4. **прогон ядра** (`sim/harness.gd`): маршруты строятся **автоматически** — BFS по рёбрам от
      каждого входа к цели, плюс крышечные «вход → якорь окна → цель» на каждое окно (якорь — из
      `trigger` окна); каждую пару соседей в маршруте проверь на существование ребра (внутренний
      инвариант `ROUTE_ADJACENCY`, не критерий приёмки); поведения — молчание и «первый доступный
      вариант»; сиды 1…5;
   5. **вывод**: таблица «маршрут → окна, которые сработали» (id, по порядку), матрица исходов
      (`extracted`/`caught`/`timeout`) по маршрутам и поведениям, окна, не сработавшие нигде
      (с якорем), число сработавших окон за прохождение (мин/среднее/макс), таблица критериев
      «имя — факт — требование — вердикт», строка детерминизма (повторный прогон одного маршрута
      даёт тот же `digest`).
   Критерии (имена — дословно, вердикт по каждому): `FORM`, `GEOMETRY`, `ENTRIES_DECLARED`,
   `OBJECTIVE_FROM_EVERY_ENTRY`, `EXIT_REACHED`, `FAILURE_REACHABLE`, `TWO_INDEPENDENT_EXITS`,
   `WINDOW_FIRED_AT_LEAST_ONCE`, `FIRING_RANGE` (5…12, ориентир 8–9 печатается отдельно).
   Код возврата: **0** — все обязательные выполнены, **1** — есть нарушенные (названы), **2** —
   вход/сборка не состоялись. Сторож вердикта (`_process`) — как в
   `docs/handoff/2026-09-27-mission-01-v2/kit/verifier/verify.gd`: аборт до `quit()` даёт код 1, а не 0.

2. **Общий модуль сценариев вмешательства.** Построение сценария (`_order_script`, `_window_sequence`,
   `_pick` из `measure_mission01.gd`) вынеси в `game/tests/order_builder.gd` и подключи **в обоих**
   инструментах. Копия этих функций в новом файле запрещена.

## Область

**Можно:** `game/tests/accept_delivery.gd` (новый), `game/tests/order_builder.gd` (новый),
`game/tests/measure_mission01.gd` (только подключение вынесенного модуля).
**Не трогать:** `game/sim/**`, `game/content/**`, `game/tests/cases/**`, `game/tests/suite.gd`,
`docs/handoff/**` (поставка — свидетельство: пробы только на копиях в `%TEMP%`), `docs/**` кроме отчёта.
Конвенции: без `class_name`, табы, комментарии и имена проверок русские, вердикт — код возврата.

## Доказательство

Пять проб на **копиях** поставки в `%TEMP%` (боевые файлы поставки сверить по SHA до и после):

| Проба | Что ломаем | Что обязано покраснеть (именем) |
|---|---|---|
| M1 | убрать одно ребро, отрезающее вход от цели | `OBJECTIVE_FROM_EVERY_ENTRY` |
| M2 | перенести якорь окна так, что оно недостижимо | `WINDOW_FIRED_AT_LEAST_ONCE` |
| M3 | сдвинуть `pos` двух помещений одного этажа вплотную | `GEOMETRY` |
| M4 | сломать форму: у окна одно качество молчания вместо четырёх | стадия 1, названный код проблемы, код 1 |
| M5 | отрезать один из двух путей к выходу от цели | `TWO_INDEPENDENT_EXITS` |

Плюс: дословный прогон инструмента на поставке (числа и код), повторный прогон (те же числа),
`measure_mission01.gd` до и после выноса модуля — **числа совпадают дословно**, гейт из
`constraints.md` §2 (preflight → `run.gd` → `run_red.gd`).
