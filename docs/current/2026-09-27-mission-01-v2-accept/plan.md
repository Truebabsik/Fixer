## Критерии приёмки

Полный разбор и обоснование — `design.md`. Коротко: обязательны K1–K7, отдельно печатаются числа
(в том числе для сравнения с таблицами отчёта исполнителя).

| Код | Критерий | Источник требования |
|---|---|---|
| K1 | `FORM` — наша пара валидатор+загрузчик: 0 проблем, миссия собирается | задание поставки §7.1 |
| K9 | `ENTRIES_DECLARED` — входов по тегу `entry` не меньше трёх | задание §2 (три входа) |
| K2 | `OBJECTIVE_FROM_EVERY_ENTRY` — цель берётся **прогоном** от каждого входа | §3.1, `07-self-check.md` §8.1 |
| K3 | `EXIT_REACHED` — группа доходит до выхода, исход `extracted` достигнут от каждого входа | §3.2, §8.3 |
| K4 | `FAILURE_REACHABLE` — провал (`caught`) достижим | §3.4, §8.4 |
| K5 | `TWO_INDEPENDENT_EXITS` — от цели ≥ 2 пути к выходу, перекрытие одного тревогой не отрезает выход | §3.2 |
| K6 | `WINDOW_FIRED_AT_LEAST_ONCE` — каждое объявленное окно срабатывает хоть раз | §8.2 |
| K7 | `FIRING_RANGE` — срабатывающих окон за прохождение 5…12 (ориентир 8–9) | §4.1, `07-self-check.md` §4.9 |
| K8 | `GEOMETRY` — `pos` у всех помещений, этаж не наезжает (шаг 4, коробка 3×3), подписи и этажи с текстами | §3.7, `07-self-check.md` §10 |

## Приёмка задачи в целом

1. Инструмент приёмки существует, запускается на **произвольной** паре файлов и краснеет
   **именованным** критерием на сломанных данных (пробы — в отчёте задачи 1).
2. Приёмка поставки проведена: K1–K8 с вердиктом по каждому, числа замеров названы.
3. Утверждения отчёта исполнителя (таблица §4.9 «маршрут → срабатывающие окна», «16 объявленных /
   8–9 срабатывающих», «перекрываемых тревогой рёбер 6», «тупиков нет») подтверждены или опровергнуты
   **прогоном**, а не чтением.
4. Вердикт приёмки вынесен и записан: принять / принять с замечаниями / вернуть, с ценой каждого
   варианта. Решение по `game/content/` (замена на v2 или отказ) зафиксировано.
5. `docs/current/2026-09-27-mission-01-v2-accept/summary.md` заполнен, решения — в `ledger.md`.
