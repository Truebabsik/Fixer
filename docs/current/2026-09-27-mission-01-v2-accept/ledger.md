## 2. 2026-09-27. Решения ведущего по процедуре

| Решение | Почему | Цена |
|---|---|---|
| Приёмка = **прогон**, а не чтение отчёта | прошлый урок (49 проблем) + `07-self-check.md` §8 | нужен инструмент, которого нет |
| Инструмент принимает **произвольную** пару «миссия + тексты» | следующая поставка будет другой топологией | чуть больше работы, чем одноразовый скрипт |
| Маршруты строятся **автоматически** (BFS + крышечные через якоря окон) | рукописные маршруты проверяли бы, что мы угадали замысел исполнителя, а не что уровень играется | покрытие маршрутов эвристическое, не «нормативные три» |
| Перекрываемые тревогой виды рёбер — **из ядра** (`Response.BLOCKED_KINDS`) | два списка расходятся молча (урок с каналами разведки) | — |
| Поставку **не правим**, пробы на копиях в `%TEMP%` | папка поставки — свидетельство о том, что сдал исполнитель | — |
| `game/content/` не трогаем до вердикта | приёмка должна судить поставку, а не подменять её | перенос — отдельная задача |
| README папки поставки приводим к факту (v1 → история git), **файлы не двигаем** | папка — запись о том, что сдал генератор; двигать сданное без нужды — риск потерять провенанс | в README будут числа двух поставок |
| Критерии K1–K8 (см. `design.md`), вердикт по ним — обязательный; исходы и доля вмешательства — числа, не вердикт | баланс не входит в приёмку уровня | вердикт не «автоматический»: решение по числам за ведущим |

**Открыто до прогона:** судьба пяти отклонений от `02-level.md` и 12 заявок движку (§2–3 отчёта
исполнителя) — решается по числам приёмки, а не до них.

**Замечено до прогона (гипотеза, требует подтверждения инструментом).** Окно `w_guard4` имеет триггер
`guard_in_sensor` на сенсоре `s_ops4` (`ops4`, `eng4`), а маршруты патрулей в данных такие:
`guard_1 main_entry1↔lobby1`, `guard_2 office2→term2→freight2`, `guard_3 stair3↔hall3`,
`guard_4 hall0→freight0→climate0`. **Ни один патруль не заходит в `ops4`/`eng4`**, а событие
`sensor_contact` в ядре возникает только у охраны (`sim.gd:_update_visibility` обходит `guards`).
Значит, окно «дежурный инженера» не может сработать никогда — класс дефекта «окно, описанное
в данных, но недостижимое на маршруте» (`07-self-check.md` §8.2). Проверка — критерий
`WINDOW_FIRED_AT_LEAST_ONCE` в задаче 3; если гипотеза подтвердится, отчёт исполнителя в §4.9
**завышает** счёт на единицу на маршрутах «главный вход» и «док» (9 → 8).

**Структурная проверка всех 16 окон (ведущий, по данным, до прогона):** для каждого окна спрошено
то, что решает его судьбу по коду ядра, — есть ли маршрут от входа через якорь к цели (`node_entered`),
заходит ли хоть один патруль в помещения сенсора (`guard_in_sensor`), пересекается ли ребро с
маршрутом (`locked_edge`). Результат: **способны сработать 15 окон, неспособно одно — `w_guard4`**.
Это второй независимый способ прийти к тому же выводу (первый — правило актёра в
`_actor_in_sensor`). Прогон инструмента — третий, и решающий.

## 7. 2026-09-27. Разбор отчёта аналитика дизайна (`reports/03-design-analysis.md`)

только агрегаты, иначе вердикт «норма выполнена» держится на выборке, которая вопрос не покрывает.

1. **`w_guard4`: вернуть поставку или принять с замечанием.** Решение — **принять с замечаниями**,

   правка данных, а не формы, и она обязана прийти с пробой «окно срабатывает».
2. **Трактовка `FIRING_RANGE`.** Критерий остаётся, но вердикт обязан сопровождаться **числами по
   маршрутам**; «ориентир 8–9 не воспроизведён на кратчайших маршрутах» идёт в отчёт приёмки как
   отдельная строка, а не прячется за агрегатом.
3. **Класс дефекта вне области (сторож вердикта).** `var code := helper(); quit(code)` не ловит аборт
   **внутри** хелпера: проба P7 дала код 0 при напечатанном `SCRIPT ERROR`, то есть ровно класс
   «ворота, возвращающие успех с ошибкой в логе» (`review-checklist.md` §3). Той же формы
   `measure_mission01.gd:142–145`. **Чиним** — задача 1б, потому что замер баланса с таким сторожем
   способен молча показать зелёный прогон на упавшем замере.
4. **`preflight` не разбирает новые инструменты.** Чиним там же: разбор всех боевых скриптов — это
   ворота, и новый инструмент обязан попадать в них, иначе его синтаксическая ошибка всплывёт в
   момент, когда он понадобится.
