# Комплект самопроверки: как прогнать наш валидатор самому

Это **копия нашей проверяющей части**: те же модули, что стоят у нас на приёмке, скопированы
дословно (побайтово) на дату выпуска пакета — **2026-09-27, схема формы `01-format.md`**.
Наш репозиторий для этого не нужен: комплект самодостаточен.

**Что это даёт:** ты прогоняешь **наш** валидатор до сдачи и видишь ровно те диагнозы, которые
увидим мы. Чего это не даёт: **приёмка всё равно идёт у нас** — комплект не заменяет её, а
позволяет прийти на неё с чистым файлом, а не с 49 проблемами.

---

## 1. Что внутри

```
kit/verifier/            ← это и есть проект, который запускается
    project.godot        минимальный проект Godot 4.7 (без автозагрузок, сцен и плагинов)
    verify.gd            раннер: читает два файла, печатает проблемы, отдаёт код возврата
    selfcheck.gd         проверка САМОГО ПАКЕТА: ищет в его файлах следы нашего репозитория
    content/validator.gd копия нашего валидатора
    content/problems.gd  копия кодов проблем
    content/loader.gd    копия загрузчика (собирает модель из проверенных данных)
    sim/mission.gd       копия модели миссии (нужна валидатору и загрузчику)
    sim/plan.gd          копия плана игрока (нужна загрузчику)
    sim/response.gd      копия группы реагирования (нужна валидатору: список перекрываемых рёбер)

kit/example/             ← образец в текущей форме, к нему же и прогоняется
    mission.example.json
    texts.example.json
```

Ничего из этого править не нужно и нельзя: изменённая копия проверяет не то, что проверяем мы.
Свой файл держи **рядом** с комплектом, а не внутри него.

## 2. Что нужно, чтобы запустить

**Godot 4.7** (любой патч-релиз 4.7.x), обычная сборка — .NET не нужна. Скачай файл, который
умеет работать из командной строки:

- **Windows:** `Godot_v4.7.2-stable_win64_console.exe` (именно `_console`: обычный `.exe` не
  покажет печать в терминале);
- **Linux:** `Godot_v4.7.2-stable_linux.x86_64`.

Дальше — **дословные команды**. Замени только пути (`<...>`) и имя исполняемого файла Godot.
**Пути к файлам давай абсолютные** — так они работают из любого каталога; почему — в разборе
команды ниже.

### Windows (PowerShell или cmd)

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path <путь к kit\verifier> --script res://verify.gd -- <путь к mission.json> <путь к texts.json>
```

Прогон на образце (подставь полный путь к распакованному пакету):

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path C:\packet\kit\verifier --script res://verify.gd -- C:\packet\kit\example\mission.example.json C:\packet\kit\example\texts.example.json
```

Прогон на своём файле:

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path C:\packet\kit\verifier --script res://verify.gd -- C:\work\mission.json C:\work\texts.json
```

### Linux

```bash
./Godot_v4.7.2-stable_linux.x86_64 --headless --path /home/you/packet/kit/verifier --script res://verify.gd -- /home/you/packet/kit/example/mission.example.json /home/you/packet/kit/example/texts.example.json
```

```bash
./Godot_v4.7.2-stable_linux.x86_64 --headless --path /home/you/packet/kit/verifier --script res://verify.gd -- /home/you/mission.json /home/you/texts.json
```

**Разбор команды, чтобы не гадать:**

| Часть | Зачем |
|---|---|
| `--headless` | без окна; комплект ничего не рисует |
| `--path <kit/verifier>` | корень проекта: здесь `res://` указывает на папку комплекта |
| `--script res://verify.gd` | что запустить |
| `--` | **обязателен**: всё после него — аргументы скрипта, а не движка |
| `<mission.json> <texts.json>` | ровно два пути, в этом порядке; **абсолютные** — надёжнее |

**Почему пути лучше абсолютные.** Движок считает относительный путь **от папки комплекта**
(`kit/verifier`), а не от текущего каталога: команда `-- .\kit\example\mission.example.json`
из корня пакета даёт `НЕ ПРОЧИТАНО … (код ошибки 7)`. Относительный путь тоже годится, если
считать его от комплекта (`..\example\mission.example.json`), но абсолютный не надо считать
вовсе. Кавычки — если в пути есть пробелы.

## 3. Что означает вывод и код возврата

**Вердикт — КОД ВОЗВРАТА процесса, а не текст.** Godot пишет в stderr безобидный шум даже при
успехе (`Failed to read the root certificate store`, `Could not create directory: 'user://logs'`) —
не считай его ошибкой.

| Код | Что значит | Что делать |
|---|---|---|
| **0** | проблем нет, миссия собрана | можно сдавать |
| **1** | проблемы есть | они напечатаны выше: код, путь, сообщение — чинить каждую |
| **2** | файлы не прочитались / не разобрались как JSON / аргументы не переданы | проверить пути и синтаксис JSON |

Как выглядит успех:

```
ФАЙЛЫ  mission: ...\kit\example\mission.example.json
ФАЙЛЫ  texts:   ...\kit\example\texts.example.json
ПРОБЛЕМ: 0
СОБРАНО: миссия «mission-example», помещений 14, рёбер 15, патрулей 3, сенсоров 3, окон 5, разведка 3, точек доступа 2
ВЕРДИКТ: проблем нет, миссия собрана (код 0)
```

Как выглядит провал (здесь у окна описано одно качество молчания вместо четырёх):

```
ПРОБЛЕМ: 1
  1. [MISSING_SILENCE] windows.w_server_door — у окна нет молчания — а оно обязано быть у каждого: молчание встроено в форму окна и приказа не тратит
ВЕРДИКТ: проблемы есть — уровень не принят (код 1)
```

**Как читать проблему:** `[КОД] путь — сообщение`. `путь` указывает место **в твоём файле**
(`windows.w_server_door.silence.bad`, `nodes.hall1.pos.x`) — по нему ошибка находится сразу.
Полный перечень кодов с объяснением — `01-format.md` §16.

**Строка `СОБРАНО:` — вторая половина проверки.** Форма может быть безупречной, а модель — не
собраться; тогда ты увидишь `СБОРКА: миссия НЕ собрана`. Это тоже код 1.

## 4. Что комплект проверяет и чего не проверяет

**Проверяет** (это и есть наши машинные проверки): типы и обязательность полей, неизвестные поля,
дубли id, ссылки на существующие объекты, диапазоны значений, достижимость «вход ↔ цель», инварианты
окон (молчание из четырёх исходов, выполнимость окна у двери, отсутствие варианта `silence`, дубли
вариантов), **запрет `unlock` у окна не про дверь** — во всех местах окна, где бывают эффекты
(варианты, четыре исхода молчания, `fallback` заявки), **замыкание маршрута патруля** (последняя
точка соединена ребром с первой), **значение канала разведки** (`drone`, `agents`, `hack`), правило
одного подброшенного пункта у агентуры, сверку ключей текстов **в обе стороны**, наличие 31
обязательного системного ключа и сборку модели уровня.

**Не проверяет** (придётся делать самому — список в `07-self-check.md`):

- смысл уровня: число срабатывающих окон, тупики, «провал достижим, но не обязателен»;
- смысловое соответствие ключа качества его тексту и то, что базовый текст не называет решающего;
- координаты помещений: валидатор смотрит только их тип, а не наложение коробок и сетку;
- уникальность `id` заявок движку;
- два независимых пути к выходу, которые не перекрывает тревога.

## 5. Проверь, что комплект жив на твоей машине

Прогони команду из §2 на **образце** — она обязана дать код 0. Если образец не проходит, комплект
разошёлся со схемой или команда собрана неверно: напиши нам, **не правь копии**.

**Четыре пробы, которые стоит сделать осознанно.** Логика та же, что у нас на приёмке: проверка
считается работающей только тогда, когда краснеет на сломанном.

1. **Сломай одно место в своём файле** — например, убери у окна одно качество молчания — и прогони.
   Ожидание: код 1 и названный `MISSING_SILENCE` на этом окне, а не «что-то не так».
2. **Удали из текстов один ключ, на который ссылаются данные** (например `window.<окно>.text`).
   Ожидание: код 1 и `MISSING_TEXT` с путём **того поля**, где ключ объявлен.
3. **Добавь в тексты лишний ключ** (не из служебных семейств `mission.`, `negotiation.`, `team.`,
   `log.`, `voice.`, `final.`, `outcome.`, `results.`, `intel.`). Ожидание: код 1 и `DANGLING_TEXT`
   на этот ключ.
4. **Разомкни маршрут патруля** — убери из `edges` ребро, которым последняя точка маршрута
   соединяется с первой (в образце это `e_stair_2_0`, замыкающее кольцо `guard_3`). Ожидание: код 1
   и `PATROL_ROUTE_OPEN` на `patrols[2].route` — «маршрут не замкнут: «stair2» и «stair0» не
   соединены ребром, а охранник идёт по кругу». Маршрут охраны — цикл (§4.1 `01-format.md`), и
   разрыв в замыкающей паре — такая же ошибка, как разрыв между соседними точками.

Если какая-то проба **не краснеет** — это находка: скажи нам, в комплекте или в валидаторе
расхождение.

## 6. Проверка самодостаточности: пакет ни на что наше не ссылается

Рядом с раннером лежит `selfcheck.gd`. Он проверяет **не твой файл, а сам пакет**: проходит
по всем его файлам и краснеет, если в них остался след нашего репозитория — путь к нашим
документам, внутренний номер нашего решения, имя нашего набора тестов, ссылка на наш разбор
или имя документа, которого в пакете нет.

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --path C:\packet\kit\verifier --script res://selfcheck.gd
```

Путь к комплекту — полный, как и в §2. Запускать **из пакета**: скрипт сам находит папку
пакета выше комплекта (это видно в первой строке вывода — `КОРЕНЬ ПАКЕТА`). Как выглядит
чистый прогон:

```
КОРЕНЬ ПАКЕТА: .../2026-09-27-mission-01-v2
ФАЙЛОВ ПРОСМОТРЕНО: 22 (пропущено по расширению: 0)
САМОПРОВЕРКА ДЕТЕКТОРА: правила сработали — dnn, docs-backslash, docs-slash, res-content, res-sim, res-tests, review
ДОКУМЕНТОВ ПАКЕТА НАЗВАНО: 8 — 00-task.md, 01-format.md, ...
НАРУШЕНИЙ: 0
ВЕРДИКТ: пакет самодостаточен — наружу ничего нашего не течёт (код 0)
```

Строка `САМОПРОВЕРКА ДЕТЕКТОРА` — не украшение: она называет правила, которые сработали на
заведомо грязной строке внутри самого скрипта. Если проверка сломана, молчит она так же, как
чистый пакет, — эта строка и отличает одно от другого.

**Код возврата:** `0` — чисто; `1` — нарушения есть (напечатаны: файл, строка, правило);
`2` — папка пакета не найдена (значит, комплект распакован отдельно; запусти из пакета).

**Зачем это тебе.** Пакет обещает: наш репозиторий тебе не нужен. Ссылка на файл, которого
у тебя нет, читается как «пакет дали неполный» — и это дефект пакета, а не твоя ошибка.
Прогони `selfcheck.gd` и приложи его вывод к письму, если что-то нашлось: полный перечень
правил — в комментарии к самому `selfcheck.gd`, там же сказано, что именно он смотрит.
