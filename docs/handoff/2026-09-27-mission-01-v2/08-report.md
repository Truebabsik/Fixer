# Отчёт о самопроверке — шаблон

Заполни и сдай как `report.md` вместе с артефактами. **Отчёт — часть результата, а не приложение:**
без него артефакт не принимается. По нему мы понимаем, где ты сомневался и что решал сам.

Заполняй по факту. Пустой раздел пиши как «нет» — это нормальный ответ. Раздел, заполненный отпиской
«всё в порядке», **хуже пустого**.

---

## 1. Что сдано

| Файл | Что внутри | Числа |
|---|---|---|
| `mission-01.json` | помещений: …, рёбер: …, патрулей: …, сенсоров: …, окон: …, блоков разведки: …, точек доступа: … | |
| `texts.ru.json` | ключей: …, из них обязательных системных: … | |
| (другие файлы, если контент разбит) | | |

**Кратко:** какое прохождение ты спроектировал — каким путём группа идёт снизу, каким сверху,
где перелом, сколько окон срабатывает на каждом из трёх путей.

**Числа заполняй по факту, из файла, а не по памяти.** Точные числа нужны нам, чтобы сверить сдачу с
тем, что увидим мы: расхождение по числу помещений или ключей означает, что мы смотрим разные файлы,
и это первое, что проверяется на приёмке. Полный список чисел — `07-self-check.md` §7.

## 6. Самопроверка по списку приёмки

Отметь **каждый** пункт: выполнено / не выполнено / с оговоркой (какой). Список — из
`07-self-check.md`; не сокращай его и не пропускай пункты, которые «и так понятно выполнены».

| Проверка | Статус |
|---|---|
| **Форма** | |
| Прогон `kit/verifier` на сдаваемых файлах — код 0 | |
| Прогон на нарочно испорченной копии — код 1 и названная проблема | |
| Игровых фраз в данных нет (только ключи и служебные `note`) | |
| **Целостность** | |

| Маршруты патрулей непрерывны (соседние узлы соединены ребром) | |
| Маршрут патруля **замкнут** (последний узел соединён ребром с первым) | |

| **Топология** | |

| Тупиков нет (в том числе после каждого исхода молчания) | |
| **Окна** | |

| Маршруты призраков отличаются от реальных | |

**Оговорки к любым «с оговоркой»** — здесь:

**Обязательно приложи к этому разделу:**

1. **Дословный прогон комплекта** — команду целиком и **весь её вывод** (ожидание: `ПРОБЛЕМ: 0`,
   `СОБРАНО: миссия «…»`, код возврата 0). Пересказ «прогнал, всё чисто» не принимается.
2. **Дословные выводы проб** из `07-self-check.md` §1.2, §1.4, §1.5 — по одной на пробу, с названным
   кодом и путём. Если проба не краснеет — это находка, и её надо назвать здесь.
3. **Таблицу чисел** из `07-self-check.md` §7: помещения, рёбра, патрули, сенсоры, окна
   (объявленные и **срабатывающие**), точки доступа, ключи данных, ключи текстов, 31 обязательный
   системный ключ, заявки движку.
4. **Таблицу «маршрут → срабатывающие окна»** из `07-self-check.md` §4.9 с итогом 8–9 окон.
5. **Доказательство отсутствия тупиков**: маршрут от цели к выходу **без** перекрываемых тревогой
   рёбер (`lift_main`, `lift_freight`), и по каждой запертой двери — какой исход молчания её
   открывает.
6. **Таблицу координат** «помещение → этаж → (x, y)» и подтверждение, что помещения одного этажа не
   наезжают.
7. **Таблицу «окно → `kind` → `trigger.type` → якорное поле → совпало»** из `07-self-check.md` §6.

## 7. Чего комплект проверить не может — и как ты это закрывал

Комплект `kit/verifier` — это **наш валидатор**, и он проверяет форму: типы, обязательность, ссылки,
инварианты окон, ключи текстов, сборку модели. Всё, что ниже, он **не проверяет** — а мы на приёмке
проверим, поэтому расскажи, как ты закрывал это сам:

| Что | Почему комплект молчит | Как ты это проверял | Чем закончилось |
|---|---|---|---|
| Цель берётся от каждого входа, а не «путь существует» | это свойство прогона, а не файла | | |
| Окна действительно срабатывают на маршрутах | комплект не знает маршрутов и состояния | | |
| Группа доходит до выхода после взятия цели | это прогон | | |
| Достижим и успех, и провал | это прогон | | |
| 8–9 срабатывающих окон за прохождение | это счёт по маршрутам | | |
| Тупиков нет (в том числе после тревоги) | комплект не знает тревоги | | |
| Помещения одного этажа не наезжают | комплект смотрит только тип `pos` | | |
| Ключ качества указывает на текст **своего** исхода | это смысл, а не форма | | |
| Уникальность `id` заявок движку | этого правила в валидаторе нет | | |

**Если что-то из этого ты не проверял — так и напиши.** Непроверенное, названное честно, мы проверим
сами и вернём с замечанием; непроверенное, выданное за проверенное, вернётся как дефект.

## 8. Что было труднее всего

Два-три абзаца честно: где форма не подошла к замыслу, где пришлось выбирать из равного, что бы ты
