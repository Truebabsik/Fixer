# Дизайн пакета постановки: генерация контента миссии

Дата: 2026-09-26. Статус: **дизайн, ждёт утверждения.**
Задача: передать генерацию контента миссии 01 отдельной модели в отдельной сессии.
Контекст: ядро П1 реализовано ([../../architecture.md](../../architecture.md)), контент-конвейера нет.

---

## 1. Зачем пакет и почему нельзя «просто попросить»

Ядро П1 принимает данными ровно пять разделов: `nodes`, `edges`, `patrols`, `sensors`, `objective` (плюс `plan`, `config`, `script` — это вход прогона, не контент). **Окна решений, их варианты и эффекты зашиты в код:** условие появления — `_maybe_open_window` (`game/sim/sim.gd:342-359`), варианты — `Window.locked_door` (`game/sim/window.gd:8-20`), эффекты — `_apply_option` / `_apply_silence` (`game/sim/sim.gd:424-449`). Парсера JSON в `sim/` и `tests/` нет ни одного.

Следствие: **всё, что определяет уровень как игру — окна из «банка факапов» (`levels/mission-01.md` §13) — сегодня принять нечем.** Просьба «сгенерируй миссию» без контракта даёт либо граф без окон, либо JSON, который некуда загрузить.

Поэтому пакет решает три вещи одновременно:

1. фиксирует **форму** (жёстко, из кода);
2. выдаёт **свободу на содержание** (генератор вправе отклоняться от `mission-01.md`);
3. требует **честный отчёт** о том, что в форму не влезло.

## 2. Границы свободы: форма против содержания

| Слой | Что это | Свобода |
|---|---|---|
| **Форма** | имена полей, типы, обязательность, идентификаторы, соглашения (обход по id, строки-ключи, никаких ссылок на функции) | **ноль** — диктует `game/sim/` |
| **Содержание** | топология этажей, названия комнат, число и состав окон, расположение патрулей, тексты | **полная** — вплоть до пересборки уровня |
| **Движок** | поведение, которого в П1 нет (см. §5) | **предложение** — генератор описывает желаемое, не выдумывает реализацию |

Правило приёмки: **каждое отклонение от `levels/mission-01.md` обязано быть в отчёте с причиной.** Без этого мы не отличим осознанное решение от ошибки чтения. Схема взята из П1: бриф задаёт форму и границы, исполнитель волен внутри, расхождения фиксируются.

## 4. Схема данных JSON

### 4.1 Уровни схемы

| Уровень | Разделы | Состояние |
|---|---|---|
| **A. Ядро принимает сегодня** | `id`, `nodes`, `edges`, `patrols`, `sensors`, `objective` | выражается 1:1, поля не меняются |
| **B. Расширение (ядро примет после правки)** | `windows`, `intel`, `access_points` | объявляем форму; парсер и валидатор пишем мы |
| **C. Вне контента** | пороги, экономика, группа реагирования, формулы | живут в `sim/` и `docs/spr/`; генератор их **не** задаёт |

### 4.2 Уровень A (жёсткие поля, факты из кода)

| Раздел / поле | Тип | Обязательность | Где читается |
|---|---|---|---|
| `nodes` | `{String: {floor:int, tags:[String]}}` | непустой | `mission.gd:64, 68-84`; `sim.gd:236` |
| `edges[].id/a/b` | String | да | `mission.gd:33, 42, 51, 58, 71-74` |
| `edges[].kind` | String из `door`/`corridor`/`lift_main`/`lift_freight`/`stairs` | да | `mission.gd:75-76`; `sim.gd:207-208` |
| `edges[].steps` | int ≥ 1 | да | `sim.gd:211` |
| `edges[].noise` | int ≥ 0 | да | `sim.gd:215-217` |
| `edges[].locked` | bool | нет (дефолт `false`) | `sim.gd:332-334` |
| `patrols[].id` | String | да | `mission.gd:80`; `sim.gd:99` |
| `patrols[].route` | `[String]`, ≥ 2 узлов, смежные узлы соединены ребром | да | `mission.gd:78-80`; `sim.gd:101-104` |
| `patrols[].period` | int ≥ 1 | нет (дефолт 4) | `sim.gd:106, 226` |
| `sensors[].id` | String | да | `mission.gd:84` |
| `sensors[].nodes` | `[String]`, непустой | да | `mission.gd:82-84`; `sim.gd:235-236` |
| `objective` | String, существует в `nodes` | да | `mission.gd:66-69`; `sim.gd:283` |

Обязательные ограничения, которые валидатор П1 **не** проверяет и которые мы требуем от данных (иначе получаем рантайм-падение, а не ошибку валидации): парность рёбер, непрерывность маршрута патруля, `period ≥ 1`, `steps ≥ 1`, `noise ≥ 0`, уникальность id, отсутствие петель `a == b`, непустой `nodes` у сенсора.

### 4.3 Уровень B: окно

```json
{
  "id": "w_bio_door",
  "trigger": {"type": "locked_edge", "edge": "e_office_it"},
  "text_key": "window.bio_door.text",
  "options": [
    {"id": "breach", "text_key": "window.bio_door.breach", "complexity": 1,
     "cost": {"noise": 8, "delay": 0}, "effects": [{"type": "unlock", "edge": "e_office_it"}]},
    {"id": "pick", "text_key": "window.bio_door.pick", "complexity": 2,
     "cost": {"noise": 1, "delay": 2}, "effects": [{"type": "unlock", "edge": "e_office_it"}]}
  ],
  "silence": {
    "text_key": "window.w_bio_door.silence",
    "good":    [{"type": "unlock", "edge": "e_office_it"}],
    "neutral": [{"type": "delay", "value": 3}],
    "bad":     [{"type": "delay", "value": 3}, {"type": "noise", "value": 5}],
    "safe":    [{"type": "delay", "value": 3}, {"type": "unlock", "edge": "e_office_it"}]
  }
}
```

Инварианты, обязательные к соблюдению (проверяет наш валидатор, см. §6):

1. **Вариант «молчать» — не в списке `options`.** Он всегда есть структурно (поле `silence`) и не требует приказа. Это прямое следствие `window.gd:5` и `sim.gd:371`.
2. `kind` окна — расширяемое перечисление; П1 знает только `locked_edge`.
3. `complexity` — 1–3 по числу условий (D31, `spr/mercs.md` §1). Поле читается только вместе с наймом; заполнять обязательно.
4. Все пользовательские строки — **только ключи**, ни одной строки текста внутри JSON.
5. Эффект — либо из перечисления известных ядру, либо `{"type": "engine_proposal", ...}` (§5).

Перечисление эффектов, которое **ядро берёт реализовать** (по факту `_apply_option` / `_apply_silence`): `unlock` (открыть ребро), `noise` (шум), `delay` (задержка), `noop`. `reroute` из первой редакции снят: поиска пути в ядре нет, и «перестроить маршрут» выразить нечем — вместо него честная пара «`delay` + `unlock`».

### 4.4 Уровень B: разведданные и призраки

```json
{
  "channel": "hack",
  "observed_at": 0,
  "entries": [
    {"kind": "patrol", "id": "guard_2", "route": ["hall", "office2"], "period": 4,
     "age_hours": 8, "false": true, "note_key": "intel.hack.patrol_note"},
    {"kind": "sensor", "nodes": ["it4"], "age_hours": 8, "false": false}
  ]
}
```

`false: true` — намеренно подброшенный пункт (D30: ложь фиксирована контентом, не кубиком). `mission-01.md` §6 требует у агентуры ровно один подброшенный пункт — ложное расписание обхода на 4-м.

### 4.5 Уровень B: точки доступа

```json
{"id": "ap_5_office", "node": "office5", "kind": "terminal",
 "actions": [{"id": "copy_data", "cost": {"steps": 4}, "effects": [{"type": "trace", "value": 3}]},
             {"id": "take_money", "cost": {"steps": 3}, "effects": [{"type": "money", "value": 40}, {"type": "trace", "value": 8}]}]}
```

Тип `trace` (след → корпоративная осведомлённость) ядру неизвестен: это `engine_proposal` из §12 «Терминал» уровня. Деньги внутри операции — D24.

### 4.6 Контракт парсера (что мы обязуемся сделать)

Требования к нашим будущим данным, вытекающие из кода:

1. **Все числа — `int` до передачи в ядро.** `JSON.parse_string` возвращает `float`; `add_node(floor: int)`, `add_edge(steps: int, noise: int)`, `add_patrol(period := 4)` типизированы (`mission.gd:15, 19, 23`).
2. **Ни одно поле не читается прямым индексом без проверки.** Сейчас `a["id"]` (`sim.gd:88`), `p["route"][0]` (`sim.gd:101`), `e["steps"]` (`sim.gd:211`) падают рантаймом при отсутствии ключа — парсер обязан валидировать до вызова `add_*`.
3. **JSON строго JSON.** Парсер Godot не принимает комментарии, висячие запятые и одинарные кавычки. Пояснения к данным живут в поле `note` (строка) или в `README` пакета, не в комментариях файла.
4. **Кодировка UTF-8 без BOM**, отступ 2 пробела, ключи в стабильном порядке — чтобы diff миссии читался человеком (`architecture.md` §1).

## 5. Невыразимое: два механизма, а не один

Решение: генератор **не угадывает** реализацию движка, но **вправе предложить** поведение. Разделяем два случая:

**A. `engine_proposal` внутри данных** — новый эффект, новое состояние, новая механика. Пишется в самом JSON в месте применения:

```json
{"type": "engine_proposal", "id": "lure_engineer",
 "want": "Инженер выходит из серверной, дверь остаётся открытой 3 шага",
 "needs": "новое состояние агента-охранника: 'вне поста' + таймер",
 "fallback": "unlock"}
```

Поле `fallback` обязательно: что делать, если мы предложение **не примем**, чтобы миссия осталась прогоняемой. Без `fallback` артефакт не принимается — иначе согласованный уровень превращается в неработающий.

**B. Раздел `needs_engine` в отчёте** — то, что не привязано к конкретному окну: расписания смен, время суток, «инженер спит», память героя.

**Что известно заранее и не должно выдаваться за новое** (в П1 есть код, но нет данных): окна и их эффекты, призраки, точки доступа, тексты. Это уровень B — расширение, которое мы делаем, а не запрос.

## 6. Приёмка: чем проверяем

| Проверка | Чем | Кто |
|---|---|---|
| Форма JSON (поля, типы, ссылки) | валидатор `game/content/` — пишем мы | мы |
| Загрузка в `Mission` без ошибок | парсер + `mission.validate()` | мы |
| Прогон миссии headless | `Harness.run_scenario` + новый кейс | мы |
| Инварианты контента (окно без «молчать», призрак без расписания, ссылка на несуществующий ключ текста, недостижимая комната) | валидатор, `architecture.md` §7.4 | мы |
| Сцепка с дизайном (отклонения обоснованы, тексты по стайлгайду) | отчёт + чтение вслух | ты |
| **Готовность к принятию** | парсер и валидатор существуют | мы |

Артефакт считается готовым, если: форма валидна, миссия грузится и прогоняется, у каждого отклонения есть причина, у каждого `engine_proposal` — `fallback`, и отчёт заполнен по шаблону.

**Что считается провалом:** JSON с комментариями или висячими запятыми; текст реплик внутри данных вместо ключей; данные, требующие изменения кода без пометки; «молчать» как элемент `options`; миссия, в которой окно может закрыться без варианта молчания; отсутствие отчёта.

## 7. Что делаем мы, после того как артефакты принесены

1. `game/content/` — парсер `Mission`/`Plan` из JSON, валидатор, коды проблем (не только русские строки, как сейчас).
2. Расширение ядра: окна, эффекты и призраки — из данных, а не из `window.gd`/`sim.gd`.
3. Решение по каждому `engine_proposal`: принять, отклонить (тогда работает `fallback`), отложить с записью в `desions.md`.
4. Кейс прогона реальной миссии → первые замеры `spr/scales.md` §10 (доля вмешательства, теснота бюджета, порог тревоги).
5. Долги П1, взятые «попутно»: общий модуль подсчёта для `run.gd`/`run_red.gd`, кейс подхода к двери со стороны `b` (`architecture.md` §10).

## 8. Что осознанно не делаем сейчас

- **Не генерируем тексты сами** — их отдаём наружу вместе с формой, потому что текст здесь основное содержание (`design.md` §17).
- **Не расширяем схему на экономику и найм** — это справочники `spr/`, они уже написаны.
- **Не трогаем фикстуру** `tests/fixtures/small_mission.gd`: она остаётся эталоном для 229 проверок ядра; реальная миссия живёт отдельно.
- **Не пишем парсер до артефактов** — иначе форма застынет раньше содержания. Единственное исключение: если артефакты придут с `engine_proposal`, парсер и валидатор придётся писать раньше, чтобы принять форму.

## 9. Риски

| Риск | Чем закрыт |
|---|---|
| Генератор придумает свою форму | `02-format.md` пишется из кода; форма — раздел с нулевой свободой |
| Согласованный уровень не грузится | обязательный `fallback` у каждого `engine_proposal`; валидатор на нашей стороне |
| Тексты напишут «не тем тоном» | стайлгайд `04-texts.md` + список запретов из `design.md` §17 |
| Пакет устареет, пока генератор работает | в `README.md` пакета фиксируется коммит `6133b60`, на который составлена схема |
| Внешняя модель ходит по репозиторию и угадывает | пакет самодостаточен: всё нужное внутри, ссылки на доки — только как первоисточник |

## 10. Решённое по открытым вопросам

1. **Версия ядра в пакете.** В `README.md` фиксируется коммит `6133b60` и версия Godot 4.7.2. Форма берётся **только** из `02-format.md`; читать код репозитория как источник формы запрещено.
2. **Объём текстов.** Весь уровень: переговоры, окна по всему банку `mission-01.md` §13 плюс сюжетные (§5.1, §9, §10, §11, §12), реплики Кира/Эхо, финальная сцена. Непокрытое — в отчёт.
3. **Самодостаточность.** Пакет самодостаточен: внешняя сессия не читает репозиторий `Fixer` вообще. Всё нужное — внутри семи файлов.
