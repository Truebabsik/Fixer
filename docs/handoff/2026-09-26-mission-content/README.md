**Кому:** отдельной модели в отдельной сессии. Репозиторий `Fixer` читать не нужно и **нельзя** — всё необходимое внутри пакета.

**Версия схемы ядра:** коммит `6133b60`, Godot 4.7.2. Форма данных берётся **только** из `02-format.md`.
**Язык:** русский. Идентификаторы в JSON — латиницей (`snake_case`).

**Начни с `example-mission.skeleton.json` после `02-format.md`** — по скелету форма видна быстрее, чем по таблицам. Скелет проверен на валидность и на прохождение нашим валидатором: в нём нет ни комментариев, ни полей, которых схема не знает; единственное допустимое поле-пояснение — `note`. Это не обещание, а машинная проверка на нашей стороне: скелет прогоняется через наш валидатор автотестом `test_handoff_skeleton.gd` (ноль проблем и миссия собирается). Тебе в репозиторий для этого ходить не нужно — но если скелет разойдётся со схемой, упадёт наш прогон, а не твоя сдача.

**Порядок важен:** `02-format.md` читается до `03-level.md`. Наоборот получается уровень, который некуда загрузить.

## Что сдаётся

```
mission-01.json          данные миссии: граф, окна, разведданные, точки доступа
texts.ru.json            все тексты по ключам, плоским словарём
report.md                отчёт по шаблону 07-report.md
```

Пути внутри пакета произвольны, имена файлов — ровно эти. Если контент не влезает в один файл данных (например, разведданные удобнее отдельно) — раздели, но перечисли все файлы в `report.md`.

## Три правила, которые важнее остальных

1. **Строки текста не живут в данных.** В `mission-01.json` — только ключи (`window.bio_door.text`), сами реплики — в `texts.ru.json`. Ни одной русской фразы внутри данных.
2. **«Молчать» — не вариант окна.** Молчание встроено в форму окна (поле `silence`) и не тратит приказ. Вариант с id `silence` в списке `options` — ошибка формы.
3. **Чего не умеет ядро — помечай, а не выдумывай.** Для нового поведения есть `engine_proposal` с обязательным `fallback` (`02-format.md` §6). Молчаливое расширение схемы своими полями — провал.

## Определение готового результата

Артефакт готов, если одновременно:

- форма проходит валидацию по `02-format.md` (поля, типы, ссылки, обязательность);
- каждый `engine_proposal` имеет `fallback`, и с учётом `fallback` миссия остаётся проходимой;
- все текстовые ключи, упомянутые в данных, есть в `texts.ru.json`, и наоборот — «висячих» ключей нет;
- `report.md` заполнен по шаблону, включая **каждое** отклонение от `03-level.md` с причиной;
- JSON — строгий (без комментариев, висячих запятых, одинарных кавычек), UTF-8 без BOM, отступ 2 пробела.

Сам проверить загрузку в движок ты не можешь — это делаем мы. Твоя задача: сдать форму, которая грузится без правок, и отчёт, по которому видно, где ты сомневался.
