# 02. Формат данных

Схема снята **из кода ядра** (коммит `6133b60`), не из проектной документации. Для каждого поля указано, где ядро его читает, — чтобы не было спора о форме.

**Три уровня схемы:**

| Уровень | Разделы | Что это значит для тебя |
|---|---|---|
| **A** | `id`, `nodes`, `edges`, `patrols`, `sensors`, `objective` | ядро читает это уже сегодня, выражается 1:1, менять форму нельзя |
| **B** | `windows`, `intel`, `access_points` | форма новая, мы напишем под неё парсер. Заполняй строго по этой схеме |
| **C** | пороги шума, эфир, группа реагирования, экономика, формулы | живёт в движке и справочниках (`05-numbers.md`); в JSON **не** задаётся |

---

## 1. Общий вид файла

```json
{
  "id": "mission-01",
  "title_key": "mission.01.title",
  "nodes": { "...": {} },
  "edges": [],
  "patrols": [],
  "sensors": [],
  "objective": "archive0",
  "windows": [],
  "intel": [],
  "access_points": []
}
```

| Корневое поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да | id миссии, `mission-01` |
| `title_key` | String | да | ключ названия уровня для интерфейса |
| `nodes` | объект | да, непустой | помещения |
| `edges` | массив | да | переходы и двери |
| `patrols` | массив | да (может быть пустым) | маршруты охраны |
| `sensors` | массив | да (может быть пустым) | зоны наблюдения |
| `objective` | String | да | id целевого помещения |
| `windows` | массив | да (может быть пустым) | окна решений |
| `intel` | массив | да (может быть пустым) | данные разведки и призраки |
| `access_points` | массив | да (может быть пустым) | терминалы, панели, камеры |

**Дополнительное поле `note` (строка) разрешено в любом объекте.** Это единственное расширение, которое ты можешь добавлять сам: пояснение для нас, которое парсер игнорирует. Не используй `note` вместо данных — и не заменяй его комментариями: комментариев в JSON не бывает.

ℹ️ Не обращай внимания на `_comment` и `_note` в файле `example-mission.skeleton.json`: это пояснения образца, в настоящем файле их быть не должно. Допустимое поле — только `note`.

## 2. Уровень A — жёсткие поля

### 2.1 `nodes` — помещения

Словарь: ключ — id помещения (латиница, `snake_case`).

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `floor` | int | да, заполнять всегда | этаж: `-1` подвал, `1`–`5` этажи, `6` крыша |
| `tags` | массив строк | нет (по умолчанию пусто) | роли помещения: `entry`, `locked_room` |

**Ограничения, которые обязана соблюдать форма** (ядро их не проверяет и падает рантаймом):
- id помещений уникальны; повтор молча затирает предыдущее;
- id непустой, только `[a-z0-9_]`.

**`tags` — свободный список, но использую рекомендуемые значения:** `entry` (вход), `locked_room` (запертая комната), `cold_archive` (холодный архив), `server` (серверная), `office`, `stair`, `lift_main`, `lift_freight`, `roof`, `terminal`, `staff` (пост охраны).

### 2.2 `edges` — переходы и двери

Массив объектов.

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да, уникальный | id ребра, префикс `e_` |
| `a`, `b` | String | да | id помещений; оба должны существовать в `nodes` |
| `kind` | String | да | строго из: `door`, `corridor`, `lift_main`, `lift_freight`, `stairs` |
| `steps` | int ≥ 1 | да | стоимость перехода в шагах |
| `noise` | int ≥ 0 | да | шум за переход (0 — тихо) |
| `locked` | bool | нет (по умолчанию `false`) | заперто ли исходно |

`kind` управляет поведением при тревоге: `lift_main` блокируется сразу, `lift_freight` — через 3 шага, `stairs` работает всегда. Числа — в `05-numbers.md` §5.

**`steps` — не декорация, а цена.** Именно она делает третий акт гонкой: с 5-го этажа до выхода должно быть больше 10 шагов, с 4-го — около 9 (`05-numbers.md` §4). Проверяй арифметику маршрута, а не только связность.

**Крыша.** Если крыша — отдельный узел, у него `floor: 6` и тег `entry`: это третий вход. Спуск с крыши в здание пешком проходит через этаж 5.

**Запрещено:** петля `a == b`; два ребра между одной парой помещений (движок вернёт первое, второе станет невидимым); `steps ≤ 0`; `noise < 0`.

### 2.3 `patrols` — маршруты охраны

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да, уникальный | id охранника, префикс `guard_` |
| `route` | массив String, ≥ 2 | да | маршрут по помещениям |
| `period` | int ≥ 1 | нет (по умолчанию 4) | через сколько шагов охранник делает следующий переход |

**Запрещено:** узел маршрута, которого нет в `nodes`; `period ≤ 0` (охранник будет двигаться каждый шаг); маршрут, где соседние помещения не соединены ребром, — движок не ищет путь, он идёт по списку, и при разрыве охранник просто застрянет.

### 2.4 `sensors` — зоны наблюдения

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да, уникальный | id сенсора, префикс `s_` |
| `nodes` | массив String, непустой | да | помещения, которые сенсор видит |

Сенсор — это то, **что игрок видит на карте**: охрана в зоне сенсора показывается красной, вне зоны — призраком. Пустой список запрещён.

### 2.5 `objective`

Строка — id помещения из `nodes`. Цель миссии, **одна**. Подвал с холодным архивом в этой миссии: комната с тегом `cold_archive`.

## 3. Ограничения, которые проверяет наш валидатор

Ты не можешь запустить валидатор, но можешь проверить себя по этому списку. Всё перечисленное — ошибка, а не предупреждение.

**Ссылочная целостность**
1. `objective` существует в `nodes`.
2. У каждого ребра `a` и `b` существуют в `nodes`.
3. Каждый узел маршрута патруля существует в `nodes`.
4. Каждый узел сенсора существует в `nodes`.
5. Каждый `edge`, упомянутый в окне (`trigger.edge`, эффект `unlock`), существует в `edges`.
6. Каждый узел в `access_points[].node` существует в `nodes`.
7. Каждый ключ из `intel[].entries[]` со ссылкой на патруль ссылается на существующий `patrols[].id`.

**Уникальность**
8. id помещений, рёбер, патрулей, сенсоров, окон, точек доступа — уникальны **в своих разделах**.
9. id агентов (`patrols[].id`) не совпадают с зарезервированными под своих: `kira`, `echo`.

**Осмысленность значений**
10. `kind` ребра — из перечисления.
11. `steps ≥ 1`, `noise ≥ 0`, `period ≥ 1`.
12. `nodes` сенсора непуст; маршрут патруля — минимум 2 узла.
13. Классы сложности вариантов `complexity` — 1, 2 или 3.

**Достижимость**
14. От стартового помещения (любого с тегом `entry`) до `objective` существует путь по рёбрам.
15. От `objective` достижим хотя бы один узел с тегом `entry` (обратный путь).

**Окна**
16. У каждого окна есть `silence` со всеми четырьмя исходами (`good`, `neutral`, `bad`, `safe`) и `text_key`.
17. У каждого окна **нет** варианта с id `silence` в `options`.
18. У каждого варианта есть `id`, `text_key`, `complexity`, `cost`.
19. id варианта уникален **внутри окна**.
20. Среди вариантов окна нет двух с одинаковым сочетанием цены и эффектов (дубль бессмысленен).
21. `unlock` в молчании стоит только у окна с триггером `locked_edge`.

**Тексты**
22. Каждый `*_key`, упомянутый в данных, присутствует в `texts.ru.json`.
23. В `texts.ru.json` нет ключей, не упомянутых в данных (кроме перечисленных в `04-texts.md` §4 как обязательные вне данных).

**Правда разведки**
24. У канала `agents` ровно **один** пункт с `false: true` — подброшенное расписание на 4-м этаже. Ноль или два — ошибка (см. `06-borders.md` §7).

## 4. Уровень B. Окна решений

Окна — душа уровня. Форма:

```json
{
  "id": "w_bio_door",
  "kind": "locked_edge",
  "trigger": {"type": "locked_edge", "edge": "e_office_it"},
  "text_key": "window.w_bio_door.text",
  "options": [
    {"id": "breach", "text_key": "window.w_bio_door.breach", "complexity": 1,
     "cost": {"noise": 8, "delay": 0},
     "effects": [{"type": "unlock", "edge": "e_office_it"}],
     "note": "грубая сила: двери конец, зато быстро"},
    {"id": "pick", "text_key": "window.w_bio_door.pick", "complexity": 2,
     "cost": {"noise": 1, "delay": 2},
     "effects": [{"type": "unlock", "edge": "e_office_it"}]}
  ],
  "silence": {
    "text_key": "window.w_bio_door.silence",
    "good":    [{"type": "unlock", "edge": "e_office_it"}],
    "neutral": [{"type": "delay", "value": 3}],
    "bad":     [{"type": "delay", "value": 3}, {"type": "noise", "value": 5}],
    "safe":    [{"type": "delay", "value": 3}, {"type": "unlock", "edge": "e_office_it"}]
  }
}
```

В каждом исходе молчания эффект — **массив**, как и в вариантах. Массив из одного элемента допустим и читается ровно так же.

### 4.1 Поля окна

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да, уникальный, префикс `w_` | id окна |
| `kind` | String | да | пока единственное поддержанное значение: `locked_edge` |
| `trigger` | объект | да | когда окно открывается (см. §4.2) |
| `text_key` | String | да | ключ текста-описания ситуации окна |
| `options` | массив | да, минимум 1 | варианты приказа |
| `silence` | объект | да | что происходит, если игрок молчит |

### 4.2 `trigger` — условие появления

| `type` | Дополнительные поля | Когда срабатывает |
|---|---|---|
| `locked_edge` | `edge` | группа подходит к запертому ребру |
| `node_entered` | `node` | группа входит в помещение |
| `guard_in_sensor` | `sensor` | охрана входит в зону сенсора |

**Другие условия — только через `engine_proposal`.** Если задуманное окно не выражается этими тремя (например «когда инженер выйдет из серверной»), используй ближайший `trigger` и опиши желаемое условие в `engine_proposal` в поле `needs`.

**Одно окно — один срабатывающий раз.** Повторные окна на одно и то же ребро не поддерживаются: если нужно, чтобы событие случилось дважды, это `engine_proposal`.

### 4.3 `options[]` — варианты приказа

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `id` | String | да, уникальный внутри окна | id варианта; `silence` запрещён |
| `text_key` | String | да | ключ текста варианта — что игрок приказывает |
| `complexity` | int 1–3 | да | сложность по числу условий (D31). 1 — «выбить», 2 — «вскрыть тихо», 3 — «три условия и больше» |
| `cost` | объект | да | цена: `noise` (int ≥ 0), `delay` (int ≥ 0, шагов) |
| `effects` | массив | да (может быть пустым) | что меняется в мире |
| `note` | String | нет | пояснение для нас |

### 4.4 `effects[]` — последствия

Известные ядру (реализуем сами):

| `type` | Поля | Что делает |
|---|---|---|
| `unlock` | `edge` | открывает запертое ребро |
| `noise` | `value` | добавляет шум сверх `cost.noise` |
| `delay` | `value` | задерживает группу на N шагов |
| `noop` | — | ничего (для вариантов, где важна только цена) |

**Эффекта `reroute` в списке нет намеренно.** Он был объявлен в первой редакции постановки и снят: у ядра нет поиска пути — маршрут группы это явный список точек, и «перестроить маршрут через помещение» выразить нечем. Если замыслу нужен уход группы в сторону, используй пару «`delay` + `unlock`» и опиши желаемое поведение в `engine_proposal` с `fallback` на неё.

Всё остальное — `engine_proposal` (§7).

### 4.5 `silence` — молчание

**Это не «вариант без цены», а отдельная ветка с четырьмя исходами.** Кто именно решает за игрока и насколько удачно — определяет **ядро**, а не контент: если в группе есть связист, он импровизирует, и кубик по seed выбирает качество исхода (D7). Если связиста нет — тактик, и исход всегда `safe`. Это единственное место с кубиком во всей игре, и оно остаётся в движке.

От тебя требуется описать **последствия каждого качества**, а не выбирать качество:

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `text_key` | String | да | ключ текста: что происходит, когда игрок молчит |
| `good` | объект-эффект | да | связист нашёл способ: как правило, сделать дело и не заплатить |
| `neutral` | объект-эффект | да | сделал как собирался, но не как ты хотел: обычно `delay` |
| `bad` | объект-эффект | да | создал новую проблему: `delay` и/или `noise` |
| `safe` | объект-эффект | да | решает тактик: обход, дольше, но предсказуемо |

Пример:

```json
"silence": {
  "text_key": "window.w_bio_door.silence",
  "good":    {"unlock": true, "edge": "e_office_it4"},
  "neutral": {"delay": 3},
  "bad":     {"delay": 3, "noise": 5},
  "safe":    {"delay": 3, "unlock": true, "edge": "e_office_it4"}
}
```

**Поля `by` в схеме нет.** Прежняя редакция постановки требовала `by` (`tactician`/`comms`/`nobody`) — это было ошибкой: значение приходит из состава группы в момент молчания, и контент не может его назначить. Если в текстах нужны разные реплики под разные исходы — заведи ключи `…silence.good`, `…silence.bad` и т.д., они допустимы.

**`unlock` в молчании уместен только для окна, привязанного к запертому ребру** (`kind: "locked_edge"`). Для `node_entered` открывать нечего: пиши `delay`, `noise` или `noop`.

**Инвариант:** вариант с id `silence` в `options` запрещён — молчание встроено в форму окна и приказа не тратит.

**Молчание никогда не проваливает миссию.** Ни одно из четырёх качеств не может вести к провалу, смерти или обязательной тревоге: `bad` — это новая проблема, а не конец миссии. Если в заготовке уровня молчание описано как безопасное («обходят, теряя время»), сохрани это.

## 5. Уровень B. Разведданные и призраки

```json
"intel": [
  {
    "channel": "hack",
    "observed_at": 0,
    "entries": [
      {"kind": "patrol", "id": "guard_2", "route": ["hall", "office5"], "period": 4,
       "age_hours": 8, "false": true, "note_key": "intel.hack.patrol_false"},
      {"kind": "sensor", "nodes": ["it4"], "age_hours": 8, "false": false}
    ]
  }
]
```

| Поле | Тип | Смысл |
|---|---|---|
| `channel` | String | `drone` / `agents` / `hack` — три канала разведки |
| `observed_at` | int | шаг, на который сделал снимок канал (для данных «до миссии» — 0) |
| `entries[].kind` | String | `patrol` / `sensor` / `guard_count` / `door_state` |
| `entries[].age_hours` | int | возраст данных в часах: источник расхождения призрака с реальностью |
| `entries[].false` | bool | **намеренно подброшено**: данные не совпадут с реальностью всегда |
| `entries[].note_key` | String | ключ текста пояснения, который игрок увидит на карте |

Для `kind: "patrol"` обязательны `id` (существующий патруль), `route`, `period`. Для `kind: "sensor"` — `nodes`. Для `guard_count` — `node` и `count`.

**Правило лжи (жёсткое):** каждый канал врёт предсказуемо и одинаково при каждом прогоне. У агентуры ровно **один** подброшенный пункт — ложное расписание обхода на 4-м этаже. Не добавляй «случайную» ложь и не делай ложными больше одного пункта у агентуры: игрок должен иметь возможность выучить эту ложь и переиграть.

## 6. Уровень B. Точки доступа

```json
"access_points": [
  {"id": "ap_office5", "node": "office5", "kind": "terminal", "text_key": "ap.office5.text",
   "actions": [
     {"id": "copy_data", "text_key": "ap.office5.copy_data", "complexity": 1,
      "cost": {"steps": 4}, "effects": [{"type": "trace", "value": 3}]},
     {"id": "take_money", "text_key": "ap.office5.take_money", "complexity": 1,
      "cost": {"steps": 3}, "effects": [{"type": "money", "value": 40}, {"type": "trace", "value": 8}]}
   ]}
]
```

| Поле | Тип | Смысл |
|---|---|---|
| `kind` | String | `terminal` / `door_panel` / `camera` / `climate` |
| `actions[].cost.steps` | int | сколько шагов занимает действие |
| `actions[].effects` | массив | `trace` (след → корпоративная осведомлённость), `money`, `unlock`, `noise`, `engine_proposal` |

Типы `trace` и `money` ядру неизвестны: деньги внутри операции и след в «Итогах» — это `engine_proposal` (см. `03-level.md` §12). Ставь их как `{"type": "trace", "value": N}` и в `report.md` §3 перечисли, что для них нужна поддержка движка.

## 7. `engine_proposal` — как просить движок

Везде, где эффекта из §4.4 не хватает, ставится объект:

```json
{"type": "engine_proposal",
 "id": "lure_engineer",
 "want": "Инженер выходит из серверной, дверь остаётся открытой 3 шага",
 "needs": "состояние охранника «вне поста» и таймер возврата",
 "fallback": {"type": "unlock", "edge": "e_office_it"}}
```

| Поле | Обязательность | Смысл |
|---|---|---|
| `id` | да | короткое имя механики, латиницей |
| `want` | да | что должно произойти, словами, одно-два предложения |
| `needs` | да | чего не хватает в движке |
| `fallback` | **да** | эффект из §4.4, который сработает, если мы предложение **не примем**. Один эффект объектом (`{"type": "unlock", "edge": "e_office_it"}`) либо массив эффектов — форматы равнозначны, парсер принимает оба |

**Без `fallback` артефакт не принимается.** Причина простая: если мы отклоним предложение, окно останется без эффекта, и уровень перестанет работать. `fallback` — это то, что делает уровень проходимым уже сегодня.

**Отдельно про эффекты `money` и `trace`:** они ядру неизвестны, но тебе не нужен для них `engine_proposal` — ставь их напрямую в `effects`, а в `report.md` §3 перечисли, что для них нужна поддержка. `engine_proposal` нужен там, где ты просишь **новое поведение**, а не новый счётчик.

Дополнительно всё, что не привязано к конкретному окну (расписания смен, «инженер спит», память героя), описывается в `report.md` §3 «требует движка» — не в данных.

## 8. Контракт парсера (что мы гарантируем, а что требуется от данных)

Мы пишем парсер так, чтобы он:

1. **приводил все числа к int** — JSON в Godot отдаёт числа как `float`, а ядро принимает `int`; дробных значений в данных быть не должно вообще (пиши `4`, не `4.0`);
2. **проверял все обязательные поля до передачи в ядро** — иначе отсутствие ключа станет падением движка, а не понятной ошибкой;
3. **требовал строгий JSON** — без комментариев, висячих запятых и одинарных кавычек (парсер Godot их не принимает);
4. **читал UTF-8 без BOM**, отступ 2 пробела, чтобы diff миссии читался человеком.

От тебя требуется ровно три вещи, следующие из этого: числа — целые; все обязательные поля заполнены; JSON — строгий.

## 9. Соглашения об именах

| Что | Префикс | Пример |
|---|---|---|
| помещение | нет, по смыслу + этаж | `hall1`, `office2`, `it4`, `archive0`, `roof` |
| ребро | `e_` | `e_hall_office2` |
| патруль/охранник | `guard_` | `guard_1` |
| сенсор | `s_` | `s_it4` |
| окно | `w_` | `w_bio_door` |
| точка доступа | `ap_` | `ap_office5` |
| вариант окна | по смыслу, коротко | `breach`, `pick`, `wait`, `lure` |

Свои агенты зарезервированы движком: `kira` (тактик, Понимание 3), `echo` (связь, Понимание 3). В `patrols` их id использовать нельзя.

**Порядок элементов в массивах = порядок хода охраны и порядок проверки.** Это влияет на прогон, поэтому порядок должен быть осмысленным (например, охрана — по этажам снизу вверх), а не случайным.
