# Поставка контента миссии 01 — как пришла (2026-09-27)

Запись, а не рабочий контент. Здесь лежит **поставка внешней сессии генератора ровно в том виде,
в каком она пришла**, чтобы правки можно было проследить до оригинала.

| Файл | Что это |
|---|---|
| `mission-01.json` | миссия: 28 помещений, 33 ребра, 4 патруля, 6 сенсоров, 11 окон, 3 блока разведки, 3 точки доступа |
| `texts.ru.json` | 123 ключа текстов, плоский словарь |
| `report.md` | отчёт генератора о самопроверке, отклонениях от `03-level.md` и заявках к движку |

**Рабочий (исправленный) контент лежит в `game/content/`** — единственная точка правды для прогонов.
Сюда ничего не «доисправляется»: файлы в этой папке — свидетельство о том, что именно сдала внешняя
сессия.

## Почему потребовалась правка

Постановка (`../2026-09-26-mission-content/`) при приёмке **не прошла наш валидатор: 49 проблем**,
миссия не собиралась вовсе. Четыре корня (подробный разбор — в
`docs/current/2026-09-27-mission-01-accept/ledger.md` §1–2):

1. `silence` у всех 11 окон записан как `{text_key, by, effect}` — один эффект вместо четырёх исходов
   (`02-format.md` §4.5), плюс поля `by`, которого в схеме нет.
2. Эффект `reroute` (5 мест) — снят из схемы намеренно (§4.4).
3. `trace_key` в точках доступа — поля не было ни в валидаторе, ни в §6 формата.
4. Окно ★27 (`w_stuck_lift`) висит на ребре, которое блокирует тревога, а не замок.

Отдельно: в отчёте генератора (`report.md`) **отсутствуют три строки приёмки** из нашего
`07-report.md` — «четыре исхода молчания», «в `silence` нет `by`», «в эффектах нет `reroute`»;
своя «самопроверка» шла их собственным `validate_mission.py`, кодировавшим их же схему,
и наш валидатор на поставке не прогонялся ни разу. Урок для следующей постановки: **пакет обязан
требовать наш прогон как доказательство**, иначе самопроверка проверяет согласованность артефакта
с самим собой.
