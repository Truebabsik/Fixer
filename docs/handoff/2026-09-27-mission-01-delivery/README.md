«доисправляется»: файлы в этой папке — свидетельство о том, что сдал исполнитель.

## 2. Что лежало здесь до неё: поставка **v1**

Файлы v1 (помещений 28, рёбер 33, окон 11, ключей 123) сохранены историей git — коммит `2b1a699`
и предыдущие. Постановка была `../2026-09-26-mission-content/`.

**Почему v1 потребовала правки.** При приёмке она **не прошла наш валидатор: 49 проблем**, миссия
не собиралась вовсе. Четыре корня (разбор — `docs/archive/2026-09-27-mission-01-accept/ledger.md` §1–2):

1. `silence` у всех 11 окон записан как `{text_key, by, effect}` — один эффект вместо четырёх исходов
   (`02-format.md` §4.5), плюс поля `by`, которого в схеме нет.
2. Эффект `reroute` (5 мест) — снят из схемы намеренно (§4.4).
3. `trace_key` в точках доступа — поля не было ни в валидаторе, ни в §6 формата.
4. Окно ★27 (`w_stuck_lift`) висит на ребре, которое блокирует тревога, а не замок.

Отдельно: в отчёте генератора v1 отсутствовали три строки приёмки из нашего `07-report.md` —
«четыре исхода молчания», «в `silence` нет `by`», «в эффектах нет `reroute`»; своя «самопроверка»
шла их собственным `validate_mission.py`, кодировавшим их же схему, и наш валидатор на поставке
не прогонялся ни разу. Урок, ради которого собран пакет v2: **пакет обязан требовать наш прогон
как доказательство** — иначе самопроверка проверяет согласованность артефакта с самим собой.

прогонов, замеров и сборки. Пока там контент v1; замена на v2 — отдельная задача **после** вердикта
приёмки (её тянет за собой `tests/cases/test_mission01_delivery.gd`, `tests/measure_mission01.gd`,
