# Что нужно экрану операции от данных и ядра

Разбор по факту: макет `docs/current/ui-operation-screen.svg` (44 текстовых элемента) и код ядра.
Зачем: экран операции — первое, что определит **форму контента** для презентации. Всё, что здесь
названо «нужно в данных», обязано попасть в схему **до** того, как обогащение уровня уедет наружу.

Обозначения: **есть** — уже читается или лежит в модели; **нужно в данных** — новое поле формы;
**нужно посчитать** — поле не нужно, но нужен счётчик/правило в ядре; **нужно в текстах** — значение
приходит ключом.

---

## 1. Что на макете

| Блок | Содержимое |
|---|---|
| Карта (левая половина) | этаж как схема: помещения (`СЕРВЕРНАЯ`, `ОФИС`, `ПЕРЕГОВОРНАЯ`, `ИТ-ОТДЕЛ`, `ДЕЖУРКА`), связи (`ЛК`, `Л1 ПАСС.`, `Л2 ГРУЗ.`), охрана, `ПАТРУЛЬ 02:00` |
| Метка данных | `данные устарели на 7 ч`, `НЕ СОВПАЛО` |
| Строка состояния | `ВХОД: ГРУЗОВОЙ ДОК 00:41`, `ЭТАЖ 4 // ИТ-ОТДЕЛ` |
| Поток | пять строк вида `> эхо: биометрия на двери` |
| Эфир | `ЭФИР 1 → 2`, `глушение`, `1 передача · ещё 2 до перехвата`, `затухание −4 / 5 шагов` |
| Командование | `КОМАНДУЕТ КИРА`, `ты не удерживал связь 4 шага`, `СВЯЗЬ НА УДЕРЖАНИИ` |
| Окно решения | текст ситуации, три варианта с пометкой цены, строка последствий молчания, `ПРИКАЗОВ 2 / 3`, `ЭФИР 1 → 2` |

## 2. Карта

| Что нужно | Состояние | Откуда / чего не хватает |
|---|---|---|
| Топология: помещения и связи | **есть** | `Mission.nodes`, `Mission.edges` (`a`, `b`, `kind`, `steps`, `noise`, `locked`) |
| Этаж помещения | **есть** | `nodes[id]["floor"]` |
| Виды связей (лифт/лестница/дверь/коридор) | **есть** | `edge.kind` из `Mission.EDGE_KINDS` |
| Зоны сенсоров | **есть** | `Mission.sensors`; уже используется для видимости охраны |
| Охрана и призраки | **есть** | `sim.guards[i].node`, `sim.ghost_positions[guard_id]`, событие `ghost_mismatch` |
| Состояние охраны (спокойна / заметила) | **есть** | `Agent.triggers`, `Agent.state` |
| **Координаты помещений** | **нужно в данных** | у узла только `{floor, tags}`. Без координат карту не нарисовать: `pos: {x, y}` **необязательным** полем — старая форма остаётся валидной, уровень без координат грузится |
| **Названия помещений** | **нужно в данных + текстах** | в узле только `tags`, а это семантика, не подпись. `name_key` у узла, значение — в текстах (`room.it4` → `ИТ-ОТДЕЛ`) |
| **Название комплекса и этажей** | **нужно в данных + текстах** | `facility_key` в корне миссии; `floor_key` на этаж. На макете `МЕРИДИАН // АРХИВНЫЙ КОМПЛЕКС` и `ЭТАЖ 4 // ИТ-ОТДЕЛ` |
| **Время наблюдения патруля** | **нужно посчитать** | `ПАТРУЛЬ 02:00` — это часы наблюдения/прогона, не шаг. Часы миссии сейчас в ядре не моделируются вовсе; до их появления показывать шаг/номер обхода |
| Ориентация ребра на схеме | не нужно | презентация выводит из координат концов |

## 3. Метки разведки (`intel`)

| Что нужно | Состояние | Откуда |
|---|---|---|
| Возраст данных | **есть** | `intel[].entries[].age_hours` — `данные устарели на 7 ч` считается прямо из него |
| Подброшенный пункт | **есть** | `entries[].false` — `НЕ СОВПАЛО` |
| Пояснение к данным | **есть** | `entries[].note_key` → тексты |
| Канал и его снимок | **есть** | `intel[].channel`, `intel[].observed_at` |

**Важно:** читать `intel` ядру **не нужно** — это данные для экрана. Сейчас их читает только
`ghost_positions` (призраки охраны). То есть каналы разведки на карте — работа презентации,
и это первое место, где «слой отображения» читает контент напрямую.

## 4. Строка состояния и поток событий

| Что нужно | Состояние | Откуда |
|---|---|---|
| Вход миссии | **есть** | `plan.route[0]`, теги `entry` |
| Строки потока | **нужно посчитать** | **дыра, самая заметная:** из ядра приходят **события**, а экран показывает **фразы** (`> эхо: биометрия на двери`). Перевода «событие → ключ текста» нет нигде; ключи `log.*` в текстах есть (8 штук), но привязки к событиям не существует |
| Часы (`00:41`) | **нужно посчитать** | часов миссии в ядре нет; либо вводим время (шаг → час), либо убираем часы с экрана |

**Предлагаемый контракт привязки** (минимальный, без нового события): таблица «тип события → ключ»
живёт в презентации, а не в ядре, потому что это вопрос показа, а не симуляции. Ядру достаточно
того, что оно уже публикует. Исключение — те строки, которым нужен факт, которого в событии нет
(см. §6, «удержание связи»).

## 5. Эфир и приказы

| Что нужно | Состояние | Откуда |
|---|---|---|
| Пул приказов | **есть** | `orders_left`, `2 / 3` |
| Отпечаток и «ещё N до перехвата» | **есть** | `radio.imprint`, порог перехвата — `docs/spr/scales.md` |
| Причина отказа | **есть** | `order_refused{reason}`: `no_orders`/`jammed`/`unknown_option`/`finished` |
| Цена передачи (+8 эфира, +1 отпечаток) | **есть** | `order_issued.data.radio` |
| Затухание −4 / 5 шагов | **есть** | `docs/spr/scales.md` §3.1, `radio.tick_decay` |
| `ты не удерживал связь 4 шага` | **нужно посчитать** | сколько шагов осталось до права говорить. `Radio` знает `can_speak`, но **числа** в наружу не отдаёт — нужен геттер `steps_until_speak(step)` |
| `СВЯЗЬ НА УДЕРЖАНИИ` (кто командует) | **нужно посчитать** | ядро знает факт глушения, но «командует Кира» — вывод из него. Либо презентация выводит из `order_refused{jammed}` / `log.radio.jammed`, либо добавляем в `result()` явное поле «кто командует» — решить до П2 |

## 6. Окно решения

| Что нужно | Состояние | Откуда |
|---|---|---|
| Текст ситуации | **есть** | `current_window.text_key` |
| Варианты с ценой | **есть** | `current_window.options[]`: `text_key`, `complexity`, `noise`, `delay` |
| Пометки «нужна легенда / тихо, но долго» | **нужно в текстах** | это часть `text_key` варианта, а не отдельное поле |
| Вариант «молчать» | **есть** | ветка `silence` добавляется последней, приказ не тратит (D23) |
| Строка последствий молчания | **есть** | `silence_key_for(w, quality)` — ключ **выбранного** качества (задача 6) |
| «+6 шагов» в строке молчания | **есть** | `delay` из применённых эффектов; в `order_silenced` едет `effect` |
| Кто решил | **есть** | `order_silenced.effect.quality` + `by` |

## 7. Итоги

| Что нужно | Состояние | Откуда |
|---|---|---|
| Исход, шаги, раненые, погибшие | **есть** | `Sim.result()` |
| Шум, эфир, отпечаток | **есть** | `result()` |
| Тексты исходов | **есть** | `outcome.*`, `results.summary` (обязательные ключи, задача 3) |
| Деньги и след | **нужно посчитать** | эффекты `money`/`trace` форма принимает, но **ядро их не обрабатывает вовсе** — их нет ни в одном `game/sim/*.gd`. Счётчиков не существует, а не «не показываются» |
| Флаги «Итогов» (`lead_known`, `cache_taken`, `reveal_operation`, …) | **нужно посчитать** | заявки `engine_proposal`: ядро применяет только `fallback`, флагов не заводит |

## 8. Вывод: что в форму, что в ядро, что в презентацию

**В форму контента (отдаётся наружу вместе с обогащением уровня):**

1. `nodes[].pos` — координаты, **необязательное** поле;
2. `nodes[].name_key` — подпись помещения, значение в текстах;
3. `facility_key` в корне + `floors[]` с `name_key` — название комплекса и этажей;
4. (опционально) `edges[].style` — если захотим различать виды связей на схеме иначе, чем по `kind`.

Всё остальное **не в форму**: возраст данных, подброшенный пункт, цены, состояния, текст окна —
уже есть либо выводится.

**В ядро (счётчики, которых нет):**

1. `money` и `trace` как счётчики «Итогов»: форма их принимает, но **ядро не обрабатывает вовсе** — эффекты не применяются и не копятся, их нет ни в одном `game/sim/*.gd`;
2. флаги знаний для «Итогов» вместо `noop`-`fallback`;
3. `steps_until_speak(step)` — число шагов до права говорить (для «ты не удерживал связь N шагов»);
4. решение: отдавать ли «кто командует» явным полем в `result()` или презентация выводит его сама;
5. решение: привязка «событие → текст потока» — таблица в презентации (рекомендую) или в ядре;
6. часы миссии — либо модель времени (шаг → час), либо отказ от часов на экране.

**В презентацию (и только туда):**

1. провайдер текстов «ключ → строка» из `mission.data.texts`;
2. интерполяция движения между шагами: `t = progress / edge.steps`, позиция — по координатам концов;
3. таблица «событие → ключ текста» для потока;
4. чтение `intel` для меток и `access_points` для терминалов;
5. темп (`STEP_SECONDS`) — декорация, а не правило: логика о времени кадра не знает.

## 9. Порядок, который из этого следует

**Обогащение уровня координатами и подписями можно отдавать наружу уже сейчас** — но пакет обязан
содержать пункты 1–3 §8 как **обязательную** часть формы, иначе топология вернётся без карты и её
придётся переделывать. **Терминалы отдавать пока нельзя:** `access_points` не исполняет никто в
`game/sim/` — сначала механика в ядре, потом контент под неё.
