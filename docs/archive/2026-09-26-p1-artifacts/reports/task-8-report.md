## Что реализовано

1. **`game/sim/window.gd`** — окно решения как чистая фабрика словарей. Инвариант D23
   закодирован дважды: вариант `SILENCE = "silence"` лежит в списке `options` каждого окна,
   и `has_silence(w)` позволяет это проверить, не переписывая окно. Молчание — не отмена,
   а полноценный ход: оно ничего не тратит и уходит в разрешение именного.
2. **Запертая дверь останавливает движение.** В `_advance_own()` сразу после получения ребра
   добавлен `continue` на `locked`. Это несущая правка: без неё агент проходил бы сквозь
   дверь, окно никогда не открывалось, и весь Task 8 остался бы мёртвым кодом.
3. **`_maybe_open_window()`** — вызывается в `advance()` после `_update_visibility()`,
   `_check_objective()` и `_check_end()`. Окно ставится последним действием шага, поэтому
   завершённая миссия окна не открывает. Окно открывается только если агент стоит в
   начале ребра (`a.node == e["a"]`) — запертая дверь видна с той стороны, откуда в неё упёрлись.
4. **`order(option_id)`** — единственная точка расхода. Молчание не тратит приказ и не трогает
   эфир; приказ тратит приказ, уходит в эфир и шумит. Отказы приходят с **именованной** причиной
   (`no_orders`, `jammed`), а не молчаливым `false`, потому что дальше по плану код ветвится
   именно по ней. Проверка `can_speak` стоит **до** `orders_left -= 1` и до `transmit`, поэтому
   при заглушённом канале передачи не происходит вовсе — контракт, оставленный на проверку
   предыдущей задачей, закрыт.
5. **`_resolve_silence`** — единственное место с кубиком (D7), ровно поэтому seed обязателен.
   Без связиста тактик решает безопасно (`quality: "safe"`, обход за 3 шага); со связистом
   бросок `rng.randf()` даёт `good` / `neutral` / `bad`.
6. **`_apply_silence` / `_apply_option` / `_apply_delay` / `_unlock`** — все эффекты вариантов
   собраны в одном месте, чтобы правило жило в одном месте.
7. **`_compromise(agent)`** — добавлен как заявлено (понадобится в Task 10). В Task 8 не вызывается.
8. Кейс зарегистрирован в `CASES` в `run.gd`.

`Understanding` намеренно не подключён — в этом плане у него нет потребителя.

## Отклонения от брифа (три, все — только имена)

Тело `window.gd`, все методы `sim.gd`, все имена ассертов и все числа перенесены дословно.
Отличия носят характер «файл иначе не разбирается в Godot 4.7.2» и проверены отдельными
пробами. Ни одно не меняет поведение или смысл.

1. **`const Window := preload("res://sim/window.gd")` → `const WindowScript := ...`**
   (и в `test_windows.gd`, и в `sim.gd`). Изолированная проба подтвердила жёсткую ошибку:
   ```
   SCRIPT ERROR: Parse Error: The member "Window" shadows a native class.
   ```
   `Window` — нативная нода Godot; тень на неё не предупреждение, а провал разбора.
   Проба с `const W := preload(...)` вернула `kind: locked_door`, `код: 0` — сам `window.gd`
   корректен, конфликтует только имя. Вызовы `Window.has_silence` / `Window.locked_door` /
   `Window.SILENCE` переименованы механически.
2. **`func _make(config := {}, agents := null)` → `func _make(config = {}, agents = null)`.**
   Godot не может вывести тип параметра из `null`:
   ```
   Parse Error: Cannot infer the type of "agents" parameter because the value is "null".
   ```
   Существующий рабочий `test_movement.gd` объявляет `func _make(route: Array)` — то есть
   у хелпера и так был типизирован только параметр; снятие вывода соответствует стилю проекта.
3. **`var a := _make(...)` / `var b := _make(...)` → `var a = _make(...)` / `var b = _make(...)`.**
   `_make` не имеет аннотации возврата, поэтому `:=` выводить не из чего:
   ```
   Parse Error: Cannot infer the type of "a" variable because the value doesn't have a set type.
   ```
   Это ровно то правило типизации, которое уже зафиксировано в контексте задачи
   («объекты из функции без аннотации возврата keep `=`»); в брифе эти две строки ему противоречили.
   Здесь же потребовался типизированный локальный: `var eff_a: Dictionary = ...` — как и предписано.

Два последних отклонения — каскад первого: они исчезли из вывода после переименования константы,
но остались бы самостоятельными блокерами.

## Находка 1 (Important) — неизвестный `option_id` принимался, тратил приказ, уходил в эфир и отчитывался успехом

**Было.** `order()` списывал приказ и вызывал `radio.transmit(...)` **до** `_apply_option`, а та на
несовпавшем id молча выходила из цикла. Итог: опечатка в идентификаторе жгла приказ, добавляла
`+8` эфира и `+1` отпечатка (порог перехвата — 3), могла сама себе устроить заклинивание, ничего не
отпирала — и возвращала `{"accepted": true, "kind": "order"}`.

**Решение контролёра.** Проверять вариант **до** любого расхода и отказывать с именованной причиной
`unknown_option`.

**Что сделано.** В `order()` после ветки молчания и **перед** проверкой `orders_left` добавлен цикл
проверки варианта по `w["options"]`; при несовпадении — `_emit("order_refused", ...)` и
`return {"accepted": false, "reason": "unknown_option"}`. `current_window` при этом не трогается,
поэтому окно остаётся открытым. Тело перенесено из брифа дословно.

## Находка 2 (Important) — порядок вызовов в `advance()` противоречил поздним брифам плана

**Решение контролёра.** Порядок реализации принят: `… видимость → контакты → цель → конец миссии →
окно`. Текст задач 8/9/10/11 в плане исправлен, рационале зафиксировано (завершённая миссия не
должна оставлять висящее неразрешимое окно). **Код не менялся** — `_maybe_open_window()` остаётся

## Остающееся сомнение

Ассерты `unknown_option` проверяют отказ, но **не** проверяют, что при отказе эфир молчит именно
потому, что передачи не было, а не потому, что её не было раньше. Здесь это неразличимо: `radio`
на момент отказа равен 0 и до окна. Порог «транслировать нечего» закрыт косвенно — ассертом
`приказ не потрачен` (`orders_left == 3`) вместе с `эфир молчит` (`radio == 0`): старая
последовательность «списать → передать → применить» даёт `2` и `8`, и это ровно то, что RED
предъявил. Отдельного счётчика вызовов `transmit` в `Radio` нет, и вводить его бриф не просил.
