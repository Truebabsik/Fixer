# Ограничения работы: читать ПЕРЕД задачей

Этот файл — общая часть всех брифов. Он не дублируется в брифах: бриф ссылается на него и содержит
только специфику задачи. Меняешь правило — меняешь здесь, и оно меняется для всех задач сразу.

Проект: `F:\WORK\Fixer`, Godot 4.7.2, GDScript, ядро работает headless.

---

## 1. Соглашения кода (из `docs/architecture.md` §6.1, обязательны)

1. **Вердикт — код возврата процесса.** `quit(0)` зелёно, `1` провал, `2` сломан приговор.
   **Текст в stderr вердиктом не является:** Godot пишет туда безобидный шум (`user://logs/...`,
   `Failed to read the root certificate store`) даже при коде 0. В этом проекте stderr уже дважды скрывал
   реальный дефект при зелёном прогоне — не полагайся на него.
2. **Никаких `class_name`** в `game/sim/`, `game/content/`, `game/tests/` — только `const X := preload("res://...")`.
   `class_name` не резолвится в headless-прогоне без обновления кэша редактора.
3. **Имя константы `preload` не совпадает с классом движка:** `const Window := ...` — жёсткая ошибка разбора
   (`shadows a native class`). Модуль окна подключён как `WindowScript`.
4. **`sim/` и `content/` не знают о нодах:** только `RefCounted`, ни `Node`, ни `SceneTree`, ни сцен.
5. **Отступы — табы.** Идентификаторы английские, комментарии и имена тестов русские.
6. **Детерминизм:** обход в фиксированном порядке (по массивам или сортировке по id), никаких решений,
   зависящих от порядка словаря. Единственный источник случайности — `rng`, засеянный из `config.seed`.
7. **Типизация:** объекты из `preload`-константы — через `:=`; из функций без аннотации возврата — через `=`
   и динамический доступ; невыводимый тип — явной аннотацией (`: Variant`).
8. **Ворота — `failed: 0`, а не общее число проверок.** Число растёт с каждым кейсом, фиксировать его
   в ожиданиях нельзя.

## 2. Команды

```powershell
# Ворота разбора: ВСЕ модули и кейсы за один процесс. Запускать ПЕРВЫМИ.
tools\Godot_v4.7.2\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tests/preflight.gd

# Полный набор: вердикт — код возврата
tools\Godot_v4.7.2\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tests/run.gd

# Красный путь: нарочно падающий кейс обязан упасть, зелёный набор — пройти. Ожидаем код 0
tools\Godot_v4.7.2\Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tests/run_red.gd
```

**Порядок обязателен:** сначала `preflight`, потом набор. Так синтаксическая ошибка называется своим файлом,
а не выглядит как поломка тестов.

**Не используй `--check-only --script res://tests/run.gd` как ворота разбора.** Она разбирает только указанный
скрипт и его статические `preload`, а кейсы и модули грузятся динамически (`load()`), поэтому при реальной
синтаксической ошибке в модуле она возвращает **код 0**, уже напечатав `Parse Error` в stderr. Именно из-за
этого 29 лишних скобок однажды прошли в дерево незамеченными; поймал их полный прогон.

## 3. Грабли среды (все проверены на практике)

| Грабля | Как обходить |
|---|---|
| `pwsh` не установлен, есть только Windows PowerShell 5.1 | Пиши под 5.1; политика исполнения запрещает `.ps1` — запускай через `[scriptblock]::Create((Get-Content file -Raw))` |
| PowerShell 5.1 читает `.gd` с кириллицей как ANSI | При правках копии дерева указывай `UTF8Encoding($false)`; после правок сверяй SHA и отсутствие `U+FFFD` |
| **Второй экземпляр редактора на одном проекте рушит окно** (пишут одни и те же кэши `.godot/`) | **Не запускай редактор (`--editor`) вообще.** `.uid` создаёт ведущий; для проб копируй дерево |
| Прогон проекта без главной сцены не завершается сам | `--quit-after <N>` не спасает: процесс висит. Не запускай проект целиком |
| Копия дерева для проб | `git worktree add --detach` в `%TEMP%` **плюс** `robocopy` всего дерева без `.git`, `.godot`, `tools`. `docs/` в копии обязателен: кейс скелета читает `../docs/...` |
| Долгие команды | Запускай в фоне (`run_in_background`) и читай вывод через `job_output`; не жди молча |
| **Два исполнителя в одном дереве** | Вердикт гейта становится **неопределённым**: он красный у обоих и не называет виновника (проверено 2026-09-27: `run.gd` 958/126 в общем дереве при зелёном 1351/0 на изолированной копии). Либо задачи сериализуются, либо гейт снимается **в изолированной копии** и в отчёте сказано, на каком дереве снят |
| **Замороженный пакет в постоянном тесте** | Пакет `docs/handoff/**` — свидетельство на дату: его копии модулей обязаны расходиться с боевым кодом. Равенство копий боевым модулям — свойство **сборки** пакета (доказать и записать тогда же), а не вечная проверка набора; иначе каждое изменение кода делает гейт красным и «врёт» про дефект |
| **Песочница теряет право записи на рабочую папку** (2026-09-27): команда падает с `SetNamedSecurityInfoW failed (Win32 5): grantWrite(<путь>)`, при этом чтение и правка файлов работают | Причина: в ACL папки есть записи песочницы с правом `Write`, но без права менять ACL, поэтому выдать себе доступ она не может. Обход: повторить **ту же** команду с `sandbox_permissions: danger-full-access` и коротким `justification` — разовый доступ работает. Не переписывай команду «по-другому» и не считай это отказом политики: это дефект окружения |
| **Внутренние токены в боевых файлах, уезжающих наружу** (2026-09-27, вскрыто пересборкой пакета) | Боевые модули и данные попадают к внешнему исполнителю **копиями** в комплект пакета. Поэтому ни в коде, ни в **комментариях**, ни в `note` данных не должно быть номеров наших решений (`D48`), ссылок на `docs/...` и имён наших тестов — иначе копия либо не проходит `selfcheck` пакета, либо уносит получателю наши внутренние отсылки. Правило проверяется кейсом чистоты пакета; правь **боевой файл**, а не копию: копия обязана быть побайтово равна боевой |

## 4. Доказательство работы: мутационные пробы

**Ни одна новая проверка не считается сделанной, пока не доказано, что она краснеет на сломанном коде.**
Порядок: скопируй дерево → сломай ровно одно место в боевом коде → прогони набор → покажи **именованный**
ассерт в выводе → откати → сверь SHA.

Почему так строго: за один этап из девяти заходов **ни один** дефект не был найден чтением кода. Все найдены
пробой, и все оказались одной природы — **что-то выглядело проверенным, не будучи им**:

- проверка, которая не может сработать (неверный тип раздела — валидатор молчал);
- ассерт, который не может покраснеть (`problems == []` при выключенной проверке);
- ворота, возвращающие 0, уже напечатав ошибку;
- аннотация возврата, приводящая словарь к `[]` и маскирующая мутацию;
- корпус значений, маскирующий половину правила (строка и число не имеют метода `has`);
- половина сообщения, которую никто не сверял;
- эталон, производный от проверяемого (обе стороны сравнения из одной константы).

Полный чек-лист этих форм — `review-checklist.md`. Если пишет исполнитель: проверь свой код по нему **сам**,
до отчёта.

## 5. Область работы

Бриф всегда называет, что можно править. По умолчанию:

- **Не трогай то, что прошло ревью** без прямого указания: любая правка там расширяет область ревью.
- **Нашёл дефект вне своей области** — опиши в отчёте, не правь.
- **Коммит делает ведущий.** Исполнитель и ревьюер оставляют изменения в рабочем дереве.
- Не создавай файлы вне указанных путей; временные пробы убирай за собой.
